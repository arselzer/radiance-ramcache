Patch B implementation audit against frozen Foundation v2
2026-10-25; source only; no Core edits/compiler/runtime/device/model invocation.

Disposition
The approved staged Engine design is implementable through a tiny-only branch in
actual Engine::start. Foundation v2 source is still immutable while the parent
runs matching gates. This audit is an implementation checklist, not activation
or a runtime result. Three concrete refinements are recorded first.

NEW exact lifetime/accounting seams to close in B

Singleton checkpoint/cache ownership: actual code and chosen narrow accessors

  Checkpoint& plus its own three maps. Checkpoint is noncopyable, owns mapped
  shards, tensors/index, sliced deque, derived/imported views/owned planes and
  import caches. It is not a plain metadata struct that can be safely adopted
  by copying or reopened after its source cache is built.

  and BoundSources retain the SAME shared SourceCheckpoint; BoundSources declares
  owner_ before actual_ so cache dies before Checkpoint. Keep this pattern in a

  tiny mode. No second open/cache or raw borrowed external Checkpoint.
- Centralize actual Engine direct consumers: sources(); read_checkpoint_metadata;
  load_plugins imported/refusal checks; postdeclare refused(); loader find and
  missing; load_vocab GGUF/tok_dir. Current references are engine_bringup.cpp
 720,798-823,880-886,1322-1323,2916-2919,4084-4095. All must use the active owner.

  checkpoint_find(), checkpoint_missing(), checkpoint_refused(), rather than
  exposing an arbitrary raw external CheckpointSources*. BoundSources currently
  lacks missing(); add that delegate ONLY in the new adapter/package. Its fn()
  must remain the actual unchanged CheckpointSources resolver. No replacement
  resolver map or forged checksum/catalog is accepted.
- Fixed source factory receives this SAME owning binding, final Rank::program,
  truthful metadata Plan and admitted budget. Derive219 actual named header/raw

  Bounded range metadata is allowed; W WeightInfo snapshot/second declaration is
  not. Export canonical physical/S1/Reader/P3 through the existing frozen helpers
  in a NEW matching transport package; work files live outside the four-file
  checkpoint root. Reaudit source namespace/object/payload/stamps before Ready.

Streams, owner, Ctx and reverse destruction
- Rank member order to preserve: Program,Plan,Pools,TinyCompute,Mover,distinct
  unique NativeBackingOwner,...Ctx,Sampler. Existing legacy ExpertRecordOwner has
  the wrong type and remains separate. Reverse destruction naturally keeps
  Pools/compute alive through Ctx/NativeOwner/Mover; explicit close is still needed.
- TinyCompute uses real TinyStream before Mover/owner/Ctx startup, maximum3
  backend streams total (compute,mover,shared loader uplink). CtxDesc borrows it
  so own_stream=false. Mover must use a precharged real tiny creation hook for
  its stream too; adding a ticket after its existing rad_stream_create is too late.
  Choose explicit owning TinyStream inside Mover or an equally explicit borrowed
  Rank transfer owner with own/destroy semantics; never double-destroy a borrowed
  stream. Preserve ordinary Mover ownership when tiny policy absent.
- Install Mover tiny retirement policy before native_record_init's actual
  bootstrap memcpy/sync (native_mover.cpp:69-75), not only after owner opens.
  Mover destructor currently flushes/syncs then frees regardless of negative
  status. Tiny path must real-drain/fail-stop BEFORE any event/backing release.
- Open actual persistent NativeBackingOwner after ordinary verification and real
  compute binding, before Ctx::init. Its session/retained leases are not owned by
  legacy record_owner. It validates final Program/Native Plan, caches fixed W
  WeightSlots (legal/charged), and borrows Mover/Pools that must outlive it.
- Engine destructor currently pre-frees some sampler/score/control buffers,
  ignores Mover drain/quiesce results, calls Ctx.shutdown, then step_state_fini,
  ranks_.clear and Registry.close. Tiny path must take its own explicit ordered
  branch before those ordinary pre-frees. Unsupported default buffers are closed
  absent, not an excuse to omit partial-startup cleanup.
- Required tiny teardown: stop/finish loader -> real mover+compute drain -> owner
  quiesce(success) -> Ctx.shutdown(with its own tiny guard) -> owner
  close_after_context_shutdown(success) -> free actual step/EOG/readback -> destroy
  NativeOwner/Mover/compute then Pools/Plan/Program -> release same-source cache,
  Checkpoint and factory generation -> Registry.close. State/ledger outlive all
  tickets/callbacks. A genuine negative drain/quiesce/close fails stop before
  dependent storage can unwind; successful earlier drains are insufficient.
- Engine ranks_ is declared before source owners, so automatic member destruction
  ALONE would destroy later source members first. Existing destructor explicitly
  clears ranks before close; new TinyState must not accidentally defeat that.
  Put stable state/ledger before ranks in member declaration order or retain an
  explicit tiny teardown that handles every partial phase before source reset.
