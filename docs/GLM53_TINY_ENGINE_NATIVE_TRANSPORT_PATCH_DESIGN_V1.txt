Target behavior: actual Engine::start through real metadata/plugins/declaration,
source export/P3/native plan/Pools/ordinary load/persistent native owner/actual
Rank::ctx initialization/step-state construction, then final TransportReady.
No Engine::serve, rank_loop, scheduler publication, model step, sampler run or

Actual source anchors and decisions
1. engine.h owns unique_ptr<Checkpoint> ckpt_ and unique_ptr<CheckpointSources>
   ckpt_src_; read_checkpoint_metadata constructs/opens them directly. There is
   NO shared Checkpoint field to adopt. engine_bringup.cpp is the only direct
   consumer: sources,metadata,plugin import choice,refusal report,load walk,vocab.
2. Engine::Rank in engine_priv.h embeds Program,Plan,Pools,Mover,Ctx,Sampler.
   Its existing record_owner is unique_ptr<ExpertRecordOwner>, NOT the distinct
   NativeBackingOwner required here. It is currently inactive in Engine startup.
3. Engine::plan currently configures Pools BEFORE pure Planner; this is wrong for
   native admission. Its generic VRAM resolution also creates2probe queues.
4. load_weights initializes Mover, then resolves source/encoding, publishes the
   residency destination, performs weight_share and stages every checkpoint
   weight. NativeStore is not an ordinary memcpy destination. Omission must move
   before destination lookup/publication and AFTER real source/share validation.
5. start creates Ctx's stream implicitly then binds Mover to it. Native owner
   opening requires a real compute stream BEFORE Ctx admission instead.
6. Engine::declare_sampler adds PERSIST sampler.tokens[I32,1], beyond the tested
   standalone Sampler graph. Engine arena/buffer counts must be measured again;
   the prior26880B arena is evidence, not an Engine arena assertion.
7. build_ctx always sets BF16 KV dtype and128KiB wire threshold. The sealed SDK
   no-KV/no-collective profile admits0defaults. Tiny build_ctx must explicitly
   normalize ONLY these unused ABI-default fields to0 and preserve every other
   exact field, then prove zero KV/attention/collectives post-declare. Default
   build_ctx remains byte-behavior equivalent. No dummy heads are permitted.
8. generic Ctx::shutdown frees arenas/tables even after a failed drain, and
   Engine/Mover destructors ignore some drain/quiesce statuses. The new tiny
   profile needs a real fail-stop retirement policy BEFORE any async submission;
   an earlier successful drain does not excuse a later genuine negative drain.

Proposed private API and storage (new names, not existing APIs)
Add engine_native_startup.h/.cpp plus the fixed tiny factory implementation.
  TinyNativeStartupRequest: noncopyable private-constructor request created by
    make_glm53_tiny_transport_request; exact profile/version/backend, bounded
    checkpoint path, separate private work-root parent, fixed caps/module pins.
    It accepts no arbitrary SourceCatalog,NativeRecordSource,Ready bool or
    independently produced checksum/manifest as a shortcut.
  TinyNativeStartupState: Engine-owned unique pimpl, fixed source factory,
    retained checkpoint binding, source setup/provider, pure metadata Plan,
    compact NativeInventory, budget/creation/retirement ledgers and sticky phase.
  Engine::set_tiny_native_startup(unique_ptr<Request>): internal/friend-only,
    empty state and before the FIRST start only; no production CLI/config flag.
  Engine::checkpoint_view(): returns tiny state's exact Checkpoint when opted,
    otherwise ckpt_.get(). checkpoint_sources_view()/sources() similarly select
    the ACTUAL cache inside BoundSources or default ckpt_src_. These are the
    centralized replacements for ALL direct consumers listed above.
  Engine::tiny_transport_snapshot(out): bounded read-only receipt for the manual
    fixture; no mutable Program/Pools/Ctx/source escape or alternate Ctx proof.

Keep default ckpt_/ckpt_src_ as their existing unique owners. In the tiny branch
the fixed source factory constructs the ONE private SourceCheckpoint owner and
its unique actual Checkpoint, and stores it in Engine::TinyNativeStartupState;
ckpt_/ckpt_src_ stay empty. BoundSources retains that SAME owner and owns the
unchanged actual Core CheckpointSources. Do not open a second Checkpoint/cache,
change all default owners to shared_ptr, or borrow an external Checkpoint whose
lifetime is merely promised. The Engine owns this source transitively through
its private state; every metadata/load/export consumer uses checkpoint_view.
Expose only bounded const find/refused/missing delegates from BoundSources for
the stock loader; no second resolver map. Destructor order is explicit below.

Rank adds unique_ptr<NativeBackingOwner> native_owner beside, not in place of,
the existing legacy record_owner. Add a checked Rank-owned compute handle BEFORE
Mover in member declaration order: Program,Plan,Pools,NativeCompute,Mover,
native_owner,...Ctx,Sampler. Reverse destruction then keeps compute/Pools alive
through Ctx/owner/Mover teardown. The NativeCompute handle does not release an
unretired stream; its policy is installed at creation. Source state outlives all
ranks and all callbacks; Registry closes after ranks as in the current destructor.

Private stream/thread tickets are reserved BEFORE creation, shared by all tiny

Tiny ordinary loader and retirement changes (default profile stays ordinary)
RelayoutPool gains an optional sealed TinyLoadProfile consumed by start; start
returns status and is exception-safe even after one worker was created. Quote
exact2workers,1MiB input arena,2*128KiB pinned slots/worker (512KiB combined),
output<=128KiB/worker,actual bounded items/queues/copy/once/event/control storage
under2MiB. Disable unbounded input new[] fallback,256MiB retained output and the
generic4GiB region only for this profile. No silent fallback on fragmentation;
bounded reservation rejects instead of holding an incomplete weight indefinitely.
All59staged descriptors/closures are bounded and source owner remains retained
until every worker,fill callback and possible DMA retires.

Crucial ownership change: the tiny profile's TWO WorkerState/Bounce objects are
POOL-OWNED, allocated/charged before starting either worker. Worker stacks borrow
their state's Bounce and NEVER destroy/free it on exit. Keep both states/buffers/
events alive across ALL worker joins and the final shared-uplink real drain.
RelayoutPool::finish is idempotent and explicitly releases these states only
after that drain; the destructor calls that checked finish. A partial-start error
sets stop/done,joins every successfully created thread,drains,then releases. The
existing worker-local Bounce automatic destructor is NOT used in the tiny path.
Its event flush alone cannot retire a copy enqueued before a failed record.

Uplink owns sticky failure/stopping/possibly-queued state under its existing
shared mutex. A Bounce slot becomes busy/possibly enqueued BEFORE memcpy_async,
not after event_record. Record/copy semantic failure stops ALL workers' future
submissions under that lock and retains every ambiguous slot/event/source. A
successfully recorded event can retire its own copy; any unrecorded/ambiguous
copy requires REAL rad_stream_sync of the shared uplink. One worker's local
destructor cannot free a possibly queued slot while another still submits.
Join/stop protocol: stop submissions -> every worker drains/retains its own busy
slots through shared state -> join all workers -> final real uplink drain ->
destroy stream -> release slots/input/closures. On unproven real drain, invoke
the explicit tiny fail-stop policy before ANY backing release. A wrapper that
returns a semantic error AFTER a real successful drain is distinguished from a
genuine negative drain; tests must witness both. This is not production recovery.

HOST h_stream_create needs real RAII: use a local unique HostStream owner, resize
the actual Task ring, construct its worker, then publish *out last. Catch bad_alloc
and system_error; no exception crosses the C ABI and caller output is preserved.
If a worker can exist at a failing later site, queue/join it before releasing
its ring/control. The current raw new/resize/std::thread sequence leaks on throw.
Actual request/thread/stream tickets are released only after destruction/join.

Terminal/shutdown discipline
Phase is sticky Requested,ColdAdmitted,SourceOwned,Declared,MetadataPlanned,
SourceReady,NativePlanned,PoolsLive,ResidentLoaded,OwnerBound,ContextBound,Ready;
any failure latches FIRST status and moves to Terminal. A same-Engine start or
request replacement refuses before work. Recovery is a fresh Engine and fresh
owned generation, never mutating/retrying the old failed Ctx/source in place.
Install a tiny-only retirement policy on CtxDesc/Mover/loader/compute ownership
before their first async work. It calls real sync and is explicitly noreturn on
a genuine failed drain in this isolated manual profile. Ctx::shutdown's existing
void/negative-drain free path and Mover destructor's ignored sync are not proof;
the tiny policy must intercept those negative returns BEFORE the free branches.
Default Ctx/Mover paths keep their existing behavior until a separate general fix.

Normal teardown/failure after queued work: stop/join loader -> real uplink drain;
quiesce NativeBackingOwner while compute/Ctx live -> actual Ctx.shutdown under
the checked retirement policy -> owner.close_after_context_shutdown -> drop owner
-> Mover retire/destroy -> Rank compute destroy -> Pools destroy. Clear ranks
before closing P3 provider/cache/BoundSources/checkpoint/work files; close Registry
last. Ctx partial-init shutdown uses the same policy. Semantic failures with proven
drains return their error after cleanup; unproven drains fail-stop instead of
unwinding into freed arenas/Pools. No bare leaked Owner Impl is treated as enough
while Mover/Pools still destruct. No production quarantine/recovery claim.
