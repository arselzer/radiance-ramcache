Defect and concrete ownership closure:
MetaOwn::finish(checkpoint.cpp39-49) publishes raw pointers into its own strings,
string vectors and pointer vectors. Builder::Builder(rad_builder.cpp110) copies
RadModelMeta shallowly into Program. V7 declare_actual copied/finished MetaOwn
in a local variable, then returned Programs after that owner died. The later
NativeInventory profile strcmp could therefore read dangling architecture data;
all initial in-helper checks occurred while the owner was alive. This source
bug invalidates V7's lifetime guarantee independently of whether that exact
runtime -18 branch was captured. No specific failed predicate is now presumed
without the new parent result.

V8/V9 Actual declares MetaOwn declaration_meta BEFORE the four Programs. Reverse
member destruction therefore destroys Programs first. Actual is allocated once
behind unique_ptr; returning that pointer does not move the MetaOwn object.
Checkpoint metadata is copied into this retained member; optional imported
quant override happens before unconditional finish(), which rebinds ALL raw
string and KV pointers even for non-imported input. No later mutation/move of
this owner is introduced.

Immediately after declare_actual returns, metadata_owner_lifetime validates
arch/name/quant pointers against the live member strings, bounded KV vector
counts and pointer arrays against the live member vectors, and every pointer
entry against its owning string. For each Program it checks exact pointer/count

negative cases/expensive Reader work and repeats after source verification.
It does not repair/rewrite Program metadata after declaration or substitute a
literal architecture string. The ordinary actual Engine uses its retained
Checkpoint/Engine-owned metadata and does not share this helper-local defect.
