Conclusion
A deliberately labeled hybrid is a plausible stock --reuse application. It is
NOT the same-checkpoint reuse contract advertised by the CLI. We would explicitly
choose official pinned FP8 expert code/scales and preserve all other logical
weight planes from the existing production container, including ten protected
BF16 experts. This retains their existing precision; it does not recover BF16
information from official FP8 or from production four-bit experts. Original
source/model revisions, protected IDs and both source digests must be recorded.
No full hybrid conversion or strict full-weight reuse coverage has been proved.

Why stock --reuse is insufficient as a strict publication guard
rad_convert.cpp828..868 compares encoding, quantizer string, options_text, rank,
ALL shape slots, and expert layer/index/slot. A mismatch silently discards the
reuse candidate and converts from current source. It does not authenticate model
or Hessian provenance. --changed disables selected reuse; it does not require all
other weights to reuse. --in-place cannot replace changed expert weights.

Rules parse/expand before reuse. Removing the generic GPTQ rule removes its CALIB
requirement. Never leave an unused rule containing unset $CALIB: recipe parsing
refuses unset variables before matching. All remaining options must match old
canonical text; options_text sorts keys but retains values as text. Existing
unmatched retained weights require special attention: their output encoding is
the new source encoding, not automatically the old container encoding. If any
such source dtype/shape differs, exact old recipe alone cannot make it reusable.
Refuse rather than silently convert; determine a narrow explicit route only if
that actual mismatch is found. Header-complete metadata comparison is first.
