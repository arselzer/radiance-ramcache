Why both aliases and the fixed-global rule are needed:
ckpt_resolve recognizes each alias as a per-tensor scalar. It represents the joined input as
affine scale[1,*], imported/nontrivial, repeating each piece's scalar logically per row.
That is usable for reading source numbers but not the PLE reader's desired one-element scale.
The recipe overrides the output encoding to affine scale[*,*], matching Ple::declare's
scale shape{1}. ckpt_rows_f32 reads the covering piece's one-element scale even for a chunk
crossing a shard boundary. The fixed quantizer emits a single whole-plane scale and streams
the code plane one row band at a time. The converter does not expand320M scales in memory.

Current import rules do NOT remove the need for this rule: import block=*x* is rejected by
the positive-integer block parser. Setting block=320001536x160 would fail the cross-piece
row-block guard at the first2500012-row shard. Smaller positive row blocks would emit many
scales rather than the one PLE expects. Do not describe those options as a lossless shortcut.

Precision analysis, not an executed byte-identity claim:
The source read converts an FP8 code to exact F32, then multiplies by BF160x3951. That scale
is209*2^-20. Finite E4M3 values have very few significand bits; their products with this
8-bit scale significand fit well inside F32 precision and stay far from F32 under/overflow.
Fixed-grid code selection uses double(v)*(1.0/exact_scale), casts to F32, then invokes the
public E4M3 encoder. Thus it should round back to the original finite FP8 centers, including
subnormal FP8 values. Positive scale preserves signed zero under the normal IEEE build.
But this is still a decode/re-encode path, and no compiler/libquant/converter test was run
by this reviewer. Claim actual code-byte identity only after the bounded test and whole-output
checks. No arbitrary NaN/sign/payload preservation or finite-payload guarantee follows from
the three source headers. The quantizer's stored scalar must remain exactly0x3951.

The existing production recipe spells scale_value as1.99317932128906e-4, a slightly truncated
decimal that rounds to the same BF16 scalar. For new conversion use the full exact value.
Do not claim exact --reuse option equality if changing that text: reuse compares encoded
quantizer/options and shapes, not merely the resulting BF16 scale.

Memory/time distinctions: fixed-grid row_block is1 even with block=*x*. The shared converter
loop uses64-MiB F32 bands, with source/reference/decode arrays and code output (roughly208 MiB
of principal band storage for this160-column table, before metadata/allocator scratch). Large
quantized jobs run one at a time; row math may use OpenMP. It does NOT allocate the full
190.7-GiB F32 table. It still reads and writes the entire47.684-GiB FP8 table for this route;
streaming is not zero I/O. All source shards are mapped, so page-cache/VA accounting remains
separate from anonymous band storage. No conversion-duration prediction is established.

Optional --reuse existing.rad can avoid rewriting a matching prior PLE payload; unchanged
weights reuse only when encoding, quantizer, options, shape and expert identities agree.
The code explicitly places same-checkpoint responsibility on the operator and does not
authenticate a source revision or calibration identity. Do not use reuse to hide a wrong
or missing source scale, or to imply official FP8 and previous BF16-derived nonexperts are
identical. A deliberately hybrid artifact must record that provenance explicitly.

A narrow Core improvement is cleaner for long-term unmodified-checkpoint support, but is
not implemented or necessary to evaluate the workaround. It would recognize the structured
PLE parent scale explicitly, require all joined shard scales to be the same verified scalar,
emit the global[*,*] encoding, and copy source code bytes plus one original scalar through
the existing imported-plane writer. Both scale-source resolution AND global output encoding
matter: a parent-name fallback alone leaves the per-row representation and PLE shape mismatch.
Avoid a generic arbitrary-parent-name heuristic. Required tests would cover unrelated parent
scales, unequal per-piece scales, dtype/shape errors, partial coverage and source lifetimes.
