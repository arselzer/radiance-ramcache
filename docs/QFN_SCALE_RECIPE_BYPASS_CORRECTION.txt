Correction to QFN shared-scale research, 2026-10-25 (source-only)

The earlier QFN_OFFICIAL_FP8_GLOBAL_PLE_IMPORT_REVIEW.txt correctly identifies the
missing parent/global PLE scale lookup, but overstates one refusal expectation:
it is NOT established that a fixed-global output recipe alone makes stock
rad-convert reject a source whose FP8 shard scales are all missing.

Exact source path in frozen radiance-src:
1. core/format/checkpoint.cpp ckpt_resolve finds each FP8 tensor but no adjacent
   _scale_inv/_scale. All w.scales entries are null; it records a source why string
   and does not establish a usable source affine encoding.
2. tools/rad_convert.cpp plan_weight can still match a quantizer recipe and obtain
   its OUTPUT encoding from the shape, overriding the missing source encoding.
3. core/format/checkpoint.cpp ckpt_rows_f32 decodes raw FP8 piece values, then
   applies scales only if at least one w.scales entry is nonnull. With ALL absent
   it returns the unscaled values. A partial-scale mixture instead enters the
   source-encoding refusal path. These cases must not be conflated.
4. The fixed output quantizer can therefore encode those incorrect unscaled
   values without authenticating the omitted source scale. A positive converter
   exit code alone is NOT scale/precision validation. Likewise it is intentionally
   allowed to requantize from a different finite source scale; wrong aliases are
   not a stock converter refusal contract.

Required workaround guard: BEFORE invoking converter, authenticate the pinned
source parent BF16[1] scalar0x3951, all shard names/header shapes, and every new
alias's BF16[1] value equality to that same scalar. Missing, mismatched, invalid
or unexpected aliases must refuse without conversion. Label those refusals as
OUR overlay-preflight behavior, not stock converter behavior. The new bounded
fixture exercises this distinction and independently checks output bytes.

No original report/source was rewritten, no converter or arithmetic test was
executed by this reviewer, and no additional model bytes were downloaded. Exact
source/executed evidence must accompany any future reusable overlay builder.
