QFN FP8 experts: a simpler single-source conversion candidate
25 October 2026 — source review and recipe preparation, not a full conversion

There is a fourth useful option alongside the three choices in
QFN_FP8_VALIDATED_PREFLIGHT_20261025.txt: use only the official FP8 checkpoint,
keep its native FP8 experts, and quantize its nonexpert weights with the same
15 nonexpert rules recorded in the current production container. This avoids
mixing releases and does not need --reuse or the hybrid's strict retained-plane
preflight. It is a different experiment: the nonexpert values may change, so it
cannot isolate the effect of upgrading only the current four-bit experts.

Prepared candidate:
  qfn8bit-conversion-plan/qwen4exp-official-fp8-experts-single-source.recipe
  SHA256 8511c79283fa0c0eee82a9f7c21b17efe9fb01fe80eca17022974fb78c3bcd51
Its companion single-source-recipe-proposal.json records the exact derivation.
The 15 nonexpert rule lines are byte-identical to the recorded production rules.
The generic expert GPTQ rule and all ten protected-BF16 cast rules are absent.
Every expert is therefore expected to take the native source FP8 import/copy
path. This proposal requires the actual complete source schema to confirm that
expectation before conversion. Casting an official FP8 expert to BF16 would not
restore the original BF16 precision that today's ten protected experts retain.

Official source:
  https://huggingface.co/Qwen/Qwen3.8-Flash-Next-FP8
  revision 236dfdf285828023ca3bcd3f37366c58a3469b13
Current four-bit container and its conversion recipe:
  https://huggingface.co/StillDeadcode/qwen3.8-next-flash-fp8-iq4r-moe

The same verified PLE scale overlay and empty quantization-descriptor override
are still required. A recipe does not replace the explicit input-scale checks.
After a complete verified source download and overlay verification, the planning
command would be:

  rad-convert ABS_VERIFIED_FP8_OVERLAY -o ABS_NEW_SINGLE_SOURCE_RAD \
    --recipe ABS_SINGLE_SOURCE_RECIPE \
    --set quantization_config.quant_method= \
    --home ABS_MATCHING_RADIANCE_HOME --plan-only -v

This command has NOT been run on the full checkpoint. Stock rad_convert.cpp
returns from --plan-only before RadWriter.begin; no model payload is written by
that mode. The actual full logical entry catalog, native expert planes, config,
tokenizer, kernel selection and output size must still be checked. The bounded
converter fixtures already test native FP8 plane copying and the global PLE
scale path, but they do not validate this full-model recipe or model quality.

The earlier 88.196 GiB host quote belongs to the hypothetical hybrid that retains
today's nonexpert encodings and ten BF16 exceptions. Do not present it as a
measured or validated quote for this new single-source candidate. If all final
shapes and nonexpert encodings agree, dropping those ten BF16 exceptions slightly
reduces expert storage; the actual complete metadata plan must establish that.

For a controlled expert-precision comparison, retain the explicit hybrid option.
For a simpler artifact sourced from one official checkpoint, evaluate this new
candidate. Both need real quality and speed measurements. No full QFN checkpoint
download, full conversion, deployment or restart was performed for this addendum.
