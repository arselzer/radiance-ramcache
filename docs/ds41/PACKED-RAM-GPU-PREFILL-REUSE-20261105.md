## Current measurable gap and smallest useful follow-up

Existing matched F5B Kh records (PHASE2-AFTER-ADMISSION table) already distinguish ranks0–3's125968 successful P1 ring-copy enqueues /2267.69GB from **189 lender reloads** (48/47/47/47). Rank0 actual drive reads fell8177→1900 and demanded drive units6958→609; its drive-wait fell38.103→3.168s. These are aggregate/producer counters, not proof of exposed critical time, same-ID overlap, physical DMA completion duration, or lender cache-hit opportunity. Do not count those189 reloads as125968 new reads or assume every lender unit is still cached.

For the current normal source, inspect existing per-rank `P1` lines: units RAM/drive/pool; actual drive_units/bytes/busy; packer packed/block counts; successful copy_bytes; wait_drive/ready/ring-full waits; and separately lent-ring lend_ram/lend_drive/lend_drive_ns/lend_read_failed. Cache stats show actual hit/miss/eviction, RAW refusals and layout refusals. Hcs adds successful staged hits/bytes/cancels; Hcn adds completed CPU helper payload/streamed bytes. None of these producer totals alone is wall-clock contribution. The guarded ledger can supply original unit identity/repetition only after ROOT executes its complete diagnostic gates.

The only small NEW conversion candidate identified here is **packed-cache→original block bytes for lender reload**, initially an opt-in CPU integer inverse into the already paid two lbuf slots. No new thread, payload bank, ring size, RAW budget, arithmetic kernel, source policy or resident format is necessary. Before implementation priority, obtain actual lender selected-unit cache overlap plus reload/first-tail critical-path evidence; current packed load guard suppresses the borrow attempt, so lend_ram=0 is not a measurement of potential overlap. A bounded diagnostic may count actual paired cache probes/true hits without touching LRU; it must preserve every failed/read counter and must not become another generic telemetry framework.

Implementation-ready boundary if that opportunity is real:

- In the existing lender worker, borrow and HOLD both actual packed HostUnit leases read-only, validate actual native shape/classes/slot bounds/source epochs and both layouts before either output write; unsupported/missing/RAW-overbudget cache entries retain the exact existing file path. Variable cache budgets and RAW capacities remain supported; nothing silently shrinks the cache.
- Add one bounded integer-only inverse primitive beside current `packed_view`/`pk_check` helpers. Validate ascending unique RAW indices, used count/range and overflow; for each row/32-value block, reconstruct exactly the e8m0 BYTE from delta or raw escape and regroup original code nibbles into the native17-byte block. GU has160 blocks/row; DN72 includes the final8-block round. Scale bytes0/1/254/255, crossing windows and all RAW escape positions must survive as bytes, with no float conversion. Existing private scalar `pk_scale` and forward `pk_round` show the exact indexing; neither currently exports a packed→block writer.
- Write directly at existing offsets0/kDnOff of the same lbuf, within original stored bytes. Release cache leases OUTSIDE producer locks after the last CPU read; keep lbuf ownership through the unchanged native copy event/drop/cancel/join lifecycle. No false device alias, HXP2 pointer published as block resident, premature credit return or new unaccounted scratch. Retain existing ordinary publication/generation/fold semantics.
- For default slots one hit reads18001280B packed and writes18800640B block before the unchanged18800640B DMA. This is a byte-volume inventory, NOT a latency/bandwidth/speed forecast. Cache DRAM contention, cancellation, CPU dispatch and the small number of reloads may make it neutral; price fresh end-to-end postlong tails and canonical N8, not only a conversion microbenchmark.
- Meaningful HOST sources must compare every GU/DN output byte to independent original-plane→native-block bytes for real full native shapes, all RAW/special/tail cases, custom capacity/missing/stale leases and unchanged guards; exercise actual lender load/read/copy/drop with a true cache hit and no file read, bounded two-lbuf backpressure/cancel/last-source retention. An exact GPU integer reformat is also possible in principle, but is not the smallest slice: it adds a launch and output writes, requires a separately paid nonoverlapping packed source/destination or an actual in-place dependency proof, and changes producer/consumer lifetime accounting. Main P1 already consumes HXP2 directly, so there is no justification for that added GPU work here. New direct packed-resident lender support would similarly need independent typed publication/dispatch proof; this note does not authorize it.

Decision: finish the existing Hcl direct-mapped startup experiment and strict DSpark/C2 roadmap first. Correct future documentation to say “generic block-copy path bypasses packed layout; P1 borrows HXP2 directly.” Do not implement another main-prefill inverse or infer a multi-times gain. Keep the bounded lender inverse as a distinct conditional candidate, with actual cache-overlap/critical-path evidence needed before priority.
