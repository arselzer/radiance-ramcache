# ds41 reports

These reports are copied byte for byte from the working folder, written 28-30 Oct 2026. Each one gives its numbers as of the time it was written. `NIGHT-LOG.md` is the running record of every A/B window and supersedes earlier estimates. The window directories it names are in `evidence/ds41/`.

Paths in the reports (`/home/as/...`) refer to the author's machine. The scratch scripts they cite under `~/.claude/jobs/...` are not included. The measurement programs they cite are in `research/ds41/`.

| Report | What it is |
|---|---|
| `REVIEW.md` | Decode review (28 Oct): what limits decode on this box, which code causes it, which changes to make first, and how other engines differ |
| `PLAN.md` | The plan built on the review: order of work, how each step is proven, and decisions left to the owner |
| `NIGHT-LOG.md` | The running log from 28 Oct 22:10 UTC: every window, result, incident and adopted switch |
| `NEXT-STEPS.md` | Next steps after the first night (29 Oct morning); later work superseded parts of it |
| `RESEARCH-2-RANKED-PLAN.md` | Ranked plan for the next optimizations (29 Oct 11:15) |
| `RESEARCH-3-CONCURRENCY.md` | Parallel sequences: why N>1 did not batch decode rows, and the scheduler switch that does |
| `RESEARCH-3-SPECDEC.md` | Speculative decoding (DSpark): why it lost, and the draft-GEMV fix (K1) |
| `RESEARCH-3-LOSSY.md` | Optional lossy speedups ranked by a fitted time model. None is implemented, and the routing trace and quality harness come first |
| `MORE-OPTIMIZATIONS.md` | A search for further optimizations through five lenses, each finding adversarially verified |
| `FP8-DENSE-DESIGN.md`, `FP8-DENSE-CRITIQUE.md`, `FP8-IMPL-REPORT.md` | FP8-stored dense weights read bit-exactly (`gemm_nt_bf16f8`): design, critique and implementation report |
| `PACKED-CACHE-IMPL-REPORT.md` | The packed-scale RAM cache (x1.044 slots) |
| `IMPL-CHAIN.md`, `IMPL-EARLY.md`, `IMPL-MISS.md`, `IMPL-PFX.md`, `IMPL-RAM.md`, `IMPL-ROUTER.md`, `IMPL-VPACK.md` | Implementation reports of the parallel work items: serial-chain overlap, early issue, miss-path switches, extended on-die prefetch, RAM reclaim, bf16 routers, packed VRAM residents |
| `IMPL-L3.md` | CCD-L3 staging, stopped at its benchmark gate (12.1% against the required 20%) |
| `PREFILL-DESIGN.md`, `PREFILL-CRITIQUE.md` | Prefill time-to-first-token model and the large-chunk prefill design, with its critique |
| `PREFILL-ENGINE-SURVEY.md` | Prefill and decode ideas from other engines |
| `PREFILL-REPLAY.md` | Offline trace replay of the consumer-suffix skip and large-chunk prefill |
| `PREFILL-200-DESIGN.md` | Design only: exact prefill at 200+ tok/s with every expert computed on the cards. It is not implemented |
| `provenance/` | Generated by `tools/ds41_refresh.py`. `ENGINE_SOURCE.json` records the exported commit and its upstream; `ENGINE_SOURCE_PINS.json` has the SHA256 of every `radiance/` file |
