Core-compatible Rad Engram staging adapter
=========================================

engram_rad_staging.h is a header-only backend for the existing generic staging
pool. It uses actual RadStream/RadEvent/copy APIs and no HIP headers or casts.
It is still not OpStager, architecture, replay or serving registration.

create_on_rank binds one nonnull borrowed ACTUAL consumer stream, a strong stream
lifetime owner, explicit caller-known device identity and nonzero arena epoch.
Caller has already bound that rank's device and must keep it bound. Every native
method/allocator call/poll/drain runs on the creator rank thread; wrong-thread
methods fail STATE without issuing device API calls. Cancellation is advisory
and can be requested elsewhere, but tickets/physical allocation owners must be
retired on their allocator's supported thread or defer cleanup there. There is
no public device-get API, so this adapter does not change or pretend to restore
an arbitrary thread's device. Host file workers should never invoke these calls.

The caller supplies CheckedRadHostAllocator. It reports a conservative allocation
charge and creates exclusive stable DMA-safe HostRowAllocation objects. Their
ownership/control must exist before physical allocation, and an error retaining
a pointer must return its owner. The generic pool immediately offers the quota
through adopt_budget_charge, even on an allocation error. A native allocator
with fallible physical free must adopt/retain that quota and allocation until a
CHECKED successful free. Plain C++ heap allocations are suitable only for HOST
backend tests. rad_dev_free is void and some backend errors only log warnings;
an empty rad_dev_last_error is NOT a physical-free proof. No built-in production
allocator silently treats it as one. Fixed borrowed model-lifetime staging or a
checked allocator supplied by the owning engine is required.

bind_arena creates a typed immutable model/device/address/extent/epoch owner.
The caller must provide a real allocation/arena lease that forbids recycling,
lending, resizing or freeing that span while referenced. The adapter checks
extent overflow, alignment, matching epoch and issuing backend. It cannot derive
ownership from an arbitrary raw pointer. A noop shared_ptr to Ctx is not an arena
lease. After an arena epoch changes, create a new adapter/binding and first drain
the old one; never reuse an old target with a different arena.

The operation pool precreates two RadEvent handles per bounded slot (1..256).
Generic submit decodes owned rows, then queues H2D and upload-ready on that same
borrowed stream. consume(ticket, callback, user) orders upload, marks reader
ownership, invokes callback with the same stream and typed destination, catches
exceptions and ALWAYS attempts a final-reader fence. The callback promises no
readers outside that stream or after it returns and must not reenter this
backend. It must keep any additional referenced buffers alive through ticket
quiescence. Cancellation before callback skips it but still explicitly seals.

Advanced order_upload marks a manual reader handoff. The caller may issue
rad_issue consumers on that SAME actual lane/stream, then finish_readers on every
path. finish_no_readers is an explicit promise and rejects a prior manual handoff.
Do not obtain a lane1 consumer's stream through rad_stream(ctx): that query names
lane0. Until the engine provides an actual active-stream handoff, use lane0 only.

Quiescent means upload AND final-reader events actually completed, never just a
success/error/cancel return. Unrecorded event handles are not queried as fences.
Completion is latched before event-slot generation reuse. Copy/record/query
failures retain the operation. A sealed operation can recover through successful
synchronization of its actual borrowed stream; failure to sync remains unsafe.
An unsealed operation stays retained because future readers were not excluded.
Use consume to avoid abandoned manual scopes after host exceptions.

close stops new work and drains all sealed records on the rank thread. It may
return unsafe while records remain; the generic tracker retains backend, stream,
source, host and arena ownership. Final-owner destruction never calls a method
using shared_from_this. Wrong-thread destruction retains the native State rather
than destroying events/stream ownership on an unbound device thread. Keep a valid
rank-thread backend handle and close explicitly. The adapter never destroys the
borrowed stream. It destroys only its quiescent event handles using the public
void teardown API; those APIs provide no checked driver-resource-free accounting.
Native event/control counts are fixed, separate from host/device byte budgets;
no claim is made that a void event destroy certifies driver RSS reclamation.

The real HOST backend tests use asynchronous worker queues, gated uploads/readers,
two assets, event generations, bounded operation slots, cancellation, callback
exceptions, partial-copy/record/query/sync failure injection, rank confinement,
strong borrowed owners, final cleanup and partially initialized event cleanup.
Fault fakes wrap the real host copy/event API; they can report failure AFTER a
copy/record was queued to exercise partial submission without a GPU fault.
One case binds a real Ctx arena, calls actual rad_issue on the borrowed stream
between order_upload and finish_readers, checks independently decoded row bytes,
and proves the arena's strong owner survives until its submitted reader retires.
Its test-only copy kernel verifies handoff/lifetime, not full Engram arithmetic.

Graph integration remains gated as described in engram_runtime_integration.README.
CPU hashing must see real host batch ownership/accepted-prefix state exactly once;
a live-pass OpStager or replay-aware host-op hook must prevent recorded packets
from skipping file/hash callbacks. End-pass cleanup must seal after failed issues
and lane joins. Drain before arena/stream shutdown. Speculation, prefix forks,
slot recycling and full CPU-vs-device logits need separate integrated tests before
serving registration. This adapter alone makes none of those claims.
