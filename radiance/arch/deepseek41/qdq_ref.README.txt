parity. No default runtime behavior changes. Whole-model BF16 intermediate,
projection, index-score and online64 attention fidelity remain separate work.

Profiles are fixed, never caller-guessed group formats:
  window_fp8:     group32, E4M3 codes, E8M0 scales, BF16 input/output.
  compressed_fp4: group16, E2M1 codes, E4M3 scales, BF16 input/output.
  index_fp4:      group32, E2M1 codes, E8M0 scales, BF16 input/output.

Each GroupResult contains32 bounded BF16/code slots, live width16/32, one scale
F32 value and one scale byte. Diagnostic codes use ONE BYTE PER LOGICAL CODE,
including FP4 codes0..15: this is NOT an implicit nibble packing, GGML ID or
physical cache ABI. GroupResult is replaced only after the whole group succeeds.

Rows are1..4096 channels, divisible by the selected group width. BF16 output is
required; logical codes, scale bytes and F32 scales are optional diagnostics.
All active output spans must have exact sizes and be disjoint from source and
each other; metadata/ranges/alignment are checked before input reads/writes.
No inplace operation. Whole-row temporary storage is bounded at about13KiB
stack, with no heap allocation or IO; row_from_f32 adds at most8KiB for a checked
F32->BF16 input conversion boundary. Source must remain immutable during a call.
Every failure leaves ALL requested outputs unchanged, even a late bad group.

Arithmetic and exact source order
---------------------------------
Pinned kernel.py41-95 and128-181 promote BF16 input to F32 for computation.
Window scale:
  a=max(absmax(group),1e-4)
  s=pow2_bits(log2_ceil_bits(F32(a * F32(1/448))))
  q=E4M3_RNE(clamp(F32(x/s),-448,448))
  y=BF16_RNE(F32(decoded(q)*s))
Compressed scale:
  a=max(absmax(group),6*2^-9)
  s=F32(E4M3_RNE(F32(a/6)))   [division, not a reciprocal multiply]
  q=E2M1_RNE(clamp(F32(x/s),-6,6))
  y=BF16_RNE(F32(decoded(q)*s))
Index scale:
  a=max(absmax(group),6*2^-126)
  s=pow2_bits(log2_ceil_bits(F32(a * F32(1/6))))
  q/y as compressed, but group32 and E8M0 scale.

The bit formula from kernel.py22-37 is specifically
  exponent_field -127 + (mantissa_bits !=0).
It is not replaced with std::log2/ceil. For positive subnormals that expression
returns-126, which is NOT a general mathematical ceil(log2). Fixed profile floors
ensure the scaled argument is normal. The public helper preserves/documentedly
tests that literal expression; the group path refuses a subnormal scale argument.
pow2_normal permits exponents-126..127; a nonpositive/nonfinite/overflowing scale
is refused. E8M0 byte is exponent+127, and decode also supports format code0=2^-127.

Signed zeros are retained through normalize, code sign, dequant and BF16 cast.
All-zero groups still have positive scales: window2^-22, compressed2^-9,
index2^-126. There is no Hadamard transform or RoPE hidden inside this operator;
callers must supply already-rotated values at the correct source boundary.

E4M3 and stronger refusal policy
--------------------------------
E4M3FN finite codes0..126 and128..254 decode with exponent bias7,3 mantissa bits,
signed zero and smallest subnormal2^-9;127/255 are reserved NaN encodings.
The checked RNE candidate chooses finite code126 at midpoint464 (even code),
then explicitly REFUSES magnitudes>464 instead of adopting a backend overflow
mode. NaN/Inf input is refused. This is a declared stronger policy, not an
assertion that official TileLang would refuse/saturate/produce NaN identically.

Actual local CPU Torch2.14.1+cpu was observed to SATURATE E4M3 casts for465,
4096,1e30,FLT_MAX and evenInf to448 (negativeInf to-448); NaN maps to a NaN
code. Therefore the fixture separately stores actual Torch conversion bytes
and candidate_accepts. Normal finite RNE cases compare to actual casts; candidate
overflow refusals are checked as policy, not misrepresented as Torch behavior.
The row generator applies the candidate refusal BEFORE calling Torch on an
overflowing compressed scale. Exact TileLang T.Cast overflow lowering remains
a future actual-kernel oracle gate.

Additional deliberate refusals: nonfinite BF16/F32 input; F32->BF16 conversion
rounding toInf; nonfinite dequantization; output BF16 conversion overflow; invalid
metadata/profile/shape/span/alias; non-RNE or FTZ/DAZ host arithmetic environment.
No exception/saturation is silently turned into a finite accepted row. The
primitive table conversions preserve their documented finite/saturation bounds.

Denormal portability gate: REQUIRED for any later GPU port
-----------------------------------------------------------
For index group32, the floor gives scale2^-126 (E8M0 code1). An input2^-127
normalizes to0.5, E2M1 code1, then dequantizes to2^-127, a NONZERO F32 subnormal
and representable BF16 subnormal (bits0x0040; negative0x8040). Flushing either
that input or product produces the wrong result. This case is a dedicated
fixture and CPU test. FTZ/DAZ default assumptions are not sufficient evidence.

The host wrapper checks FE_TONEAREST and actual gradual-underflow probes. It
does not change FP control settings; ordinary/probe arithmetic can set exception
status flags. Arithmetic-only detail::interpret_group is separated from fenv,
FTZ/DAZ and span/alias validation so a later device port has explicit boundaries.
A GPU port MUST establish its own F32 denormal contract and pass the tiny case;
host fenv validation or BF16 byte storage alone does not prove it. If native
instructions flush, use a separately validated bit/exponent reconstruction path
or refuse that profile; never claim zero is an acceptable numerical tolerance.
Build the CPU candidate without fast-math and with -ffp-contract=off.

-----------------------------------
