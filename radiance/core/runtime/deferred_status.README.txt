Opt-in deferred device-validation status (contract version 1)
===========================================================

This is an optional kernel-plugin contract, not a RadKernelInfo layout change.
Plugins without BOTH exports keep their original launch pointers and serving
path: no latch allocation, capture/copy, event wait or Engine phase split. Ctx
makes only cold/per-pass disabled checks; there is no per-issue null-hook check.

abi/rad_deferred_status.h defines an 8-byte RadDeviceStatus {int32 code,uint32 op}.
The optional rad_plugin_deferred_status_version export must return 1, and
rad_kernel_deferred_status(row_index) returns a collector function or NULL for a
row without asynchronous validation. Incomplete pairs, unsupported versions or
non-null collectors on host rows are refused before plugin registration. A row
combining a collector with a self-releasing collective (collective kind 2) is
also refused transactionally: collector failure must not mask RAD_LINK_ENDED
and cause a second release of the same link hold. Opted plugins' collective
traits are staged exactly once before open/publication; legacy trait invocation
order stays unchanged. Opted
rows are conservatively non-concurrent/non-chainable; their extra latch writes
are outside the ordinary operand schema.

rad_deferred_status_capability.h separately declares the core's host-only
rad_core_deferred_status_version()->1 probe. A plugin that requires collection
can weakly probe it in rad_plugin_open and refuse an older engine that would
otherwise ignore the new optional exports under the same RadKernelInfo ABI.
Metadata/reference libraries that do not require the contract need no gate.

A collector sees the ORIGINAL RadArgs.instance, all current tensor descriptors,
the actual issue scratch pointer, a persistent core device latch, source op ID
and the actual active-lane RadStream. It runs immediately after successful kernel
enqueue and before any later issue can recycle scratch or an explicit status
operand. It must enqueue without allocation/host synchronization, reduce any
negative source status, atomically CAS the first error into latch.code and let
only that winner write latch.op. It must not clear an earlier error. Parent
libds41 collectors cover its scalar scratch status and routed/latent status arrays.
Successful collector enqueue still does not mean successful device validation.

Only opted IssuePlan launches get a wrapper. It reconstructs the original args
instance, calls the body, then collector on the same stream and forwards errors.
Legacy launch pointers/instances remain unchanged. Ctx allocates fixed state:
one 8-byte device latch, one 8-byte pinned readback, one reset event and one done
event. Wrapper controls are sized at bind for the static issue table. There is no
per-issue readback allocation or variable pinned ring. Version 1 admits only ONE
unretired pass per Ctx and disables tapes, speculation/draft passes and issue-ahead,
so a single bank cannot be overwritten by a later pass.

Version 1 is model-pass only. Each opted wrapper checks its stable, non-movable
Ctx status owner BEFORE body or collector: begin must have succeeded and the
frame must still be pending and unsealed. An opted sampler/late issue after
seal, after await or before begin returns RAD_E_STATE without body/output writes
or a collector launch. It cannot silently collect into a retired flag that the
next pass resets. The owner outlives its bound issue plans and disables access
before shutdown can retire the raw device latch.

Pass begin queues latch reset on lane0. An already existing lane1 explicitly waits
behind that reset; a lane created mid-pass already starts behind lane0 in the
existing lane_init contract. Each collector runs before scratch reuse on its own
lane. Ctx's existing end-of-step lane join orders lane0 after every lane1 collector.
It then copies the persistent word to pinned readback and records a HOST_WAIT
completion event. A never-recorded event is not used as proof: failed capture or
record falls back to successful stream drain only to retire owned storage and
still reports the enqueue failure. A failed sync leaves storage pending.

Ctx::run_step remains enqueue-only. Ctx::await_device_status waits for the owned
copy, validates code/op attribution and returns the real device failure, naming
rank, op ID and op name in step_error(). A second pass before retirement is
refused. Engine uses THREE separate joined releases: kIssueModel enqueues and
joins HOST results, kIssueStatus awaits completed validation and joins results,
then kIssueSampler may run. The first join must precede every completion wait:
a synchronous refusal can skip an op another rank has already queued. The check
also precedes checkpoint_save, drafter/ahead issue, collect/commit and prefix/state
publication, including prefill with no logits; embedding executes both model and
status phases before collection while omitting only the sampler release.

The NEW opted Engine profile currently refuses TP>1 before any model batch.
The phase handoff alone cannot cancel a peer's unmatched device collective, a
blocked enqueue/ring reservation, or a teardown drain. The device API has no
cancel-and-quiesce contract, so bounded multi-rank failure recovery is UNPROVEN.
Legacy plugins/TP serving do not opt into this guard. Logical-rank HOST tests
below validate phase ordering, not supported multi-GPU Engine execution. A future
multi-rank profile needs a proven backend cancellation/quarantine protocol (or a
reviewed supervised process-fatal policy with a bounded watchdog) first.

Semantic validation failure is fatal for this experimental profile. Other
layers may already have mutated device cache state; the Engine goes through
fail_loop, fails queued/running requests, refuses new submissions and exits with
an error. No in-process retry/recovery is promised. A synchronous run_step error
can skip await because Engine immediately fails; shutdown drains both lanes before
freeing latch/readback. If either drain fails, the new status resources are
quarantined until process exit rather than freed on an unproven completion.
The preexisting core free API is void; this is the Engine's fatal teardown policy,
not checked physical-free accounting or a reusable cache allocator.

Tests
-----
The ABI C11/layout test pins size 8, alignment 4 and offsets 0/4 independently in C
and C++. Loader fixtures cover absent/valid/incomplete/unsupported/host-row pairs.
Real HOST Ctx tests enqueue a status into scratch, capture it and overwrite the
same scratch slice before checking; the captured negative status survives while
actual scratch reads back zero. They cover first lane1 creation, next-pass reset
ordering on an existing lane, a non-null original instance in body AND collector,
malformed attribution, pending-bank protection and explicit speculation refusal.
Late-issue regressions check body/collector call counts, a body output marker and
actual scratch contents at before-begin, after-seal and after-await boundaries.
A two-rank threaded scaffold runs real Ctx/readback phases with the SAME phase helper
as Engine and issues actual sampler rad_issue copies only after both ranks pass;
one failing rank leaves both published token slots untouched. A synchronous
refusal fixture holds peer work behind a gate and proves the HOST join returns
without entering ANY completion/sampler phase. Its gate is explicitly opened
before test teardown; this does not emulate real collective cancellation.
The test collector
is a single-reporter async copy to exercise the core handoff; the GPU collector's
atomic sticky-first-error behavior requires independent actual libds41 GPU checks. No HOST test pretends enqueue success proves the device result.

Future work before enabling replay/speculation/pipelining
--------------------------------------------------------
A shared latch is an extra side effect not represented in ordinary tape hazard
ranges. Re-enabling replay needs correct reset/capture boundaries and atomic
latch dependence in hazard ordering, plus repeat/audit tests with unchanged
pointers and changed flag contents. Speculation needs acceptance-aware state
rollback/fatal semantics. Issue-ahead needs a bounded bank per live pass and an
all-rank validation gate before each sampler/state publication. None is inferred
from current enqueue results or silently enabled for version 1.
