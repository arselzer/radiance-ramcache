DeepSeek V4.1-Flash-1017 CPU reference stage

This branch now has a small serial reference, configuration validation and four
host reference operations. It still has no DeepSeek serving registration or
packed GPU graph. The current serving model/configuration is unaffected.

Components

arch/deepseek41/config.h normalizes pinned ISTA GGUF and official HF metadata,
including the explicit deepseek41/deepseek_v41/deepseekv41 aliases. It checks
contradictory fields and unsupported semantics, preserves the full backbone and
draft schedules, and derives distinct KV, index-K, top-k and candidate ownership.
Its rotating FFN spans remain aligned to source super-scale blocks. Existing
rad_weight_shard_span and span_parts APIs can express unequal source ranges;
GPU graph/kernel integration still needs implementation and validation.

arch/common/rad_ds41_ref.h provides explicit FP32 mathematical primitives:
RMS normalization, linear projections, shifted mHC/Sinkhorn coefficients,
carried-pre collapse, residual expansion, sqrt-softplus routing, asymmetric
SwiGLU clamps, adjacent-pair RoPE/YaRN and inverse output rotation, sparse
attention with sinks, index scores, newest-block candidate pinning, grouped
output projection, partial ratio-1/2 compression and a window ring.

arch/deepseek41/attention_ref.h composes low-rank Q, sliding KV, source-owned
compression and index keys, source/consumer top-k reuse, candidate filtering,
inverse output rotation and grouped output. Index keys consume the latent
BEFORE it is rotated for the compressed KV cache. The sequence owns its state;
steps stage changes, and snapshots/restore are allowed at completed-token
boundaries and tied to exact model/sequence identity. Prefix restoration includes
partial compressor groups, ring positions, compressed KV and index-key caches.
Transient per-token candidate/top-k frames are reset, never carried from a prior
request. Small full-history NumPy goldens test the causal domain independently
from the C++ ring/incremental implementation.

arch/deepseek41/engram_ref.h consumes supplied compressed-token maps and hash
controls. It preserves order/head layout, mapped pad IDs, int64-safe products,
DEAD barriers and bounded per-sequence n-gram history. Row lookup is a callback,
not a full-table allocation. The gate uses per-copy RMS, fused q*k weighting
and the official copysign sqrt clamp, including its non-.5 positive-zero gate.
There is no convolution. Actual official forward bodies are executed by the
fixture generator with a minimal NumPy tensor facade; exact source hashes are
pinned. The two table/metadata conventions of ISTA and Unsloth are not aliased.

arch/deepseek41/block_ref.h composes Engram-before-attention, the two shifted
mHC sublayers, normalized MoE routing, all supplied experts plus a shared expert,
and the final head with the LAST FFN pre-mix. Routing weights multiply activated
intermediates BEFORE down-projection input rounding. Expert accumulation follows
ascending expert ID. Local block results commit after success. A stateful
attention callback is external: the caller must roll it back if a later layer
fails. The integrated tiny-network test snapshots/restores both attention and
Engram history, including failures after earlier layers advanced.

Registered host operations

libref exports ds41_hc_prepare, ds41_hc_collapse, ds41_router_topk and
ds41_sparse_attn with complete schema/operand shape descriptions. Preparing
mHC returns current coefficients; a separate collapse consumes previous_pre.
I/O supports the documented f32/f16/bf16 boundaries where applicable; control
coefficients/routing remain f32. The new operation documentation and existing
reference sweep registry are checked together. All new operations are host-only.

Numerical contract and limits

The main path is an FP32 semantic oracle. Optional BF16 boundaries in the block
and Engram references are explicit and separately checked. These helpers do NOT
simulate official FP8 window caches, FP4 index/latent quantizers, packed expert
activation quantization, or optimized BF16 probability rounding. Matching this
oracle is necessary but insufficient for a production packed path. Exact top-k
ties use ascending IDs/positions in the oracle; Torch's tie ordering is not
specified. Tests avoid presenting tie parity as a model guarantee.

FP32 primitive comparisons generally use 3e-6 absolute +2e-5 relative, attention
intermediates 2e-5 absolute +2e-5 relative, and complete tiny blocks 8e-6 absolute
+2e-5 relative. Long-position RoPE allows 8e-4 absolute +4e-5 relative for
float32 frequency/libm differences; inverse roundtrips have tighter checks.
Hash IDs, routing selections in non-tied fixtures and replayed state/logits are
exactly compared. Golden README files give precise per-fixture contracts.

The serial reference stores logical FP32 weights and copies its small caches
for transactions/prefix snapshots. This is intentional for deterministic tiny
tests. It is outside the real model's memory budget and must not become the
model-size execution strategy. No model-quality, 262K capacity, GPU correctness
or performance claim follows from these tests.

Validation and next implementation gate

Seven deepseek41_*_test binaries have 65 cases. The integrated network traverses
six attention layers, consumes hashes once per token, replays after a wrapped
window and half-filled C2 group, rolls back after an Engram read failure, and
interleaves independent sequences. The previous importer tests and existing
ref_test also pass. docs/OPS.md agrees with the schemas this host build declares;
existing device-only rows remain unchecked in the host-only documentation run.

Next: lossless canonical-to-GGUF packed layouts for IQ2_XXS/IQ2_XS/IQ2_S/IQ3_XXS
and suitable dense Q5_K/Q8_0 readers, then gfx1201 kernels, bounded IQ4_NL Engram
I/O, real graph/state ownership and numerical/quality gates. Do not treat IQ
vector grids as w4nl/w5nl, Q5_K as ParoQuant w5, or Q8_0's group32 as a compiled
group128 w8 kernel. See the research NEXT_KERNEL_LAYOUT_REVIEW.txt for source
rejection paths and the proposed CPU round-trip tests.

Full weights, GPU validation, benchmarking, deployment and restarts remain
outside this source-only work window and require the user's later go-ahead.
