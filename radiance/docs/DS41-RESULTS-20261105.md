# ds41 results and experiment status, November 5, 2026

The overview table reports validated results from `ds41-stable` (compiled runtime `f84b23db`,
`libr4d` SHA-256 prefix `92bd7719`). The uncached prefill measurements use four RX 9070 XT cards, a 192 GiB
expert cache, 2,048-token chunks and a fixed 131,072-token reservation. They do not qualify every
later `main` runtime merge. The prefix-cached follow-up used a 32,768-token reservation.
This publication changes documentation only.

## Validated prefill admission

Admitting every selected expert into the existing bounded RAM cache avoids repeated drive reads
on later chunks. It changes cache admission, while retaining the same weights, routing and arithmetic.

| Original prompt | Default admission, TTFT | Admit-all, TTFT | Reduction | Measurement |
|---|---:|---:|---:|---|
| 6,817 tokens | 17.163 s | 13.244 s | 22.8% | one quiet pair, `ab-20261104T115653Z` |
| 47,917 tokens | 100.254 s | 61.789 s | 38.4% | OFF/ON/ON/OFF means, `ab-20261104T121517Z` |
| 99,987 tokens | 240.4594 s | 151.3235 s | 37.069% | OFF/ON/ON/OFF means, `ab-20261105T160034Z` |

The overview's prefill throughput uses the original replies' `timings.prompt_per_second`, rather
than deriving it from TTFT: 514.86 tok/s for the 6,817-token prompt and 775.67 tok/s mean for the
47,917-token prompt (772.43 and 778.91 in the two runs). At 99,987 tokens, admit-all measured
656.15 and 665.80 tok/s, a mean of 660.97 versus 416.43 for default admission (+58.72%);
the OFF endpoint drift was 7.60%. The field measures computed prompt tokens
from the first scheduled step to first token, excluding parsing, tokenization and admission wait.
All these requests have zero prefix-cache hits.

After each 47,917-token prefill, the original eight held-out requests ran at concurrency eight.
Admit-all measured 46.50 and 47.83 tok/s total, versus controls of 46.51 and 46.83. Pair means
were 47.16 versus 46.67 tok/s; wave time was 14.00 versus 14.08 seconds. This is a no-regression
guard, without a claim of a repeatable decode gain. Total decode rate is concurrency times the
mean `timings.predicted_per_second`, consistently with the existing table.

After each quiet 99,987-token prefill, the same original N8 wave measured pair means of
47.3029 versus 47.9545 tok/s, while wave wall time was neutral at 13.9895 versus 14.0133 s.
This decode guard supports the prefill recommendation; it does not establish a broad decode gain.
The long request's own 66-token reply had OFF/ON mean individual server decode rates of
18.8791 versus 17.9070 tok/s (-5.15%); the ON runs varied from 14.32 to 21.49 tok/s (50.05% spread).
That variability does not establish a causal regression, and the subsequent N8 guard is separate.

Across the earlier 6.8K/48K windows, all 80 original replies and prompt/generated counts matched their qualified
references, as did all five captured full prefill digests. The recommendation remains specific to
the tested 192 GiB cache budget. Smaller or changing budgets retain the general `LCP_ADMIT=128`
fallback until separately measured.

The further 100K/prefix window passed all 84 original replies and prompt/generated counts,
all 14 full prefill hashes and all nine joined server exits. Its quiet 13-turn prefix-cached
pair reduced summed TTFT from 68.9714 to 56.7298 s. This is exploratory single-pair timing;
the separate hash-instrumented admit-all arm supplies exactness evidence and is timing-ineligible.
The 192 GiB recommendation already existed; this extends qualification to 100K prompts at a
fixed 131K reservation and prefix-cached turns at a fixed 32K reservation.
Smaller/dynamic cache budgets and the optional expert-worker combination remain unqualified here.

## Read-ahead with admit-all

A further Qa8/Qa0/Qa0/Qa8 screen on the same four-XT/192GiB/2K-chunk setup passed all
75 original replies/counts, three full cold prefill hashes and eleven joined server exits.
For the warmed 6,817-token prompt after an original N8 wave, disabling speculative read-ahead
reduced mean TTFT from 12.8833 to 12.3527 s (-4.12%); control endpoint drift was -0.84%.
This is a warmed-prompt result, separate from the cold-prompt overview table.

For cold 47,917-token prompts, TTFT was 76.4876/68.2309/67.5445/67.3402 s in that order.
The apparent -5.60% pair-mean improvement is inconclusive because the controls drifted -11.96%.
The subsequent N8 decode guard stayed neutral: 46.4820 versus 46.3925 tok/s (-0.19%), with
wave wall time 14.1067 versus 14.0914 s. The general read-ahead default stays eight; the existing
harness-specific Qa0 recommendation and variable-cache fallback remain unchanged.

## DSpark prototype at 32K, one stream

The prototype's fresh six-server performance window (`ab-20261105T145020Z`) passed all 96
original code/chat replies and generated counts, native checks, origin/policy gates and joined
stops, followed by an independent production-normal check. On the original code prompts,
OFF/ON/ON/OFF means were 24.917 to 29.188 tok/s (+17.14%), using the mean server-reported
per-request decode rate. This qualifies the prototype runtime `55a8aec7` at 32K and one stream.

The earlier 29.79 tok/s DSpark result remains valid. It used a different decode profile,
metric and baseline-output era, so the new matched gain is not a new absolute speed record.
The overview's ordinary held-out decode range of 28-30 tok/s is unchanged and uses a different
workload. No 128K, concurrent, auxiliary-worker, cancellation or prefix-cache DSpark promotion
follows from this finite window.

A separate current-profile PLAIN bracket used accepted/prototype/prototype/accepted order
across four fresh windows. All 64 original code replies/counts, native checks and joined stops
passed, with independent production-normal checks after every window. Mean server-reported
rates were 24.832 for the accepted engine and 24.645 for the prototype with DSpark off (-0.75%).
The accepted endpoints changed by +0.92%; the prototype repeat changed by -2.47%.
This finite comparison does not establish a causal 0.75% regression or a large prototype slowdown.
It does not make the earlier and current DSpark workloads equivalent.

## Checkpoint audit

All 1,119 other neural tensors passed the declared conversion mappings: unchanged BF16/F32 values,
decoded FP8 to BF16, BF16 to F32, and the two derived conversions. The audit covered 16,834,990,528
destination bytes with zero refused entries or mismatches. Independently regenerated integer
Engram controls matched all seven arrays (129,384 words).

Native MXFP4 expert codes and E8M0 scales are preserved. The two ISTA IQ4_NL Engram tables remain
additional quantization. Optimization exactness is against this hybrid imported baseline; neither
the audit nor reply matching establishes equivalence to an independent official runner.
