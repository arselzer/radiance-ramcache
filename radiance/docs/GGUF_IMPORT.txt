Lossless GGUF block import (experimental source branch)

This adds checkpoint conversion primitives, not a DeepSeek V4.1 serving plugin.
It does not make the complete IQ2_XS model runnable in Radiance. Architecture,
packed AMD kernels, Engram storage and TP/state integration remain separate work.

Checkpoint input

Open the first -00001-of-NNNNN.gguf file. The checkpoint reader opens every shard,
keeps every mapping alive, validates split counts/ordering/tensor totals and
refuses duplicate tensors and conflicting repeated metadata. Metadata-only first
shards are supported. Missing/truncated files fail through the GGUF reader.

For a GGUF checkpoint, rad-convert --add accepts an unsplit GGUF sidecar. Its
unique tensor names join the namespace; it never replaces the core model's
architecture/tokenizer metadata. Split or partially described sidecars fail.
Architecture arrays retain every element rather than a display summary.

Packed block conversion

Quantiser plugins may offer optional rad_checkpoint_import_count/at exports
(abi/rad_import.h). Old plugins without them still load. Partial interfaces,
malformed descriptors and duplicate (source_format, source_type) pairs fail
before registration. Existing ABI structures/version do not change.

libquant offers lossless import for its 19 standard GGML formats. This path
unpacks already chosen codes/scales/codebooks into canonical affine planes;
it does not invoke a quantisation search, require an imatrix or expand weights
to f32. Explicit quantising recipe rules still perform their requested operation.

The converter enables importers on its checkpoint explicitly. Raw checkpoint
serving remains restricted to trivial forms. An architecture must accept the
planned encodings and resolve kernels before conversion can write anything.
Expert slices and equal-format row joins are supported; column joins or mixed
source formats within one logical weight decline lossless import.

All output planes stream together in a row band bounded by the converter's
64 MiB band budget over packed input plus row-plane output, per worker. Shared
codebooks/constants are small and written once per weight. This avoids scanning
a hundred-GiB source separately for every output plane.

Compatibility limits

Numeric GGML type IDs are not universally safe identifiers. The reader and
importer must agree on both named type and block geometry. Private Radiance
rad4_* formats are not registered as standard GGUF importers. In particular,
Unsloth's newer MXFP8=43 conflicts with Radiance's private rad4_q4=43. Those files
need a deliberate reader/format extension, not an alias or a guessed decoder.

The DeepSeek checkpoint mixes IQ2_XXS, IQ2_XS, IQ2_S and IQ3_XXS experts with
Q5_K/Q8_0 and float/control weights; Engram is IQ4_NL. A family label is not a
uniform dtype. Full payload hashes/real-block sampling and full conversion have
not been performed on this branch. CPU synthetic tests do not prove model quality,
262K runtime capacity, GPU correctness or inference performance.

Validation

Configure a host-only build (RAD_WITH_HIP=OFF, RAD_WITH_FFMPEG=OFF,
RAD_BUILD_TESTS=ON), then build checkpoint_import_test, checkpoint_gguf_test,
checkpoint_test, format_test, quant_ggml_test and abi_layout_test.
checkpoint_import_test runs the actual rad-convert binary against tiny synthetic
files and compares decoded container values with an independent GGML fixture.
The two converter fixtures live outside the serving plugin scan and cannot run
inference. See tests/data/golden/gguf-import.README.txt for oracle provenance.

The subsequent host-only native-layout bridge is described in GGUF_REPACK.txt.
It preserves original blocks in both directions for the six target expert/dense
formats, with strict bounded APIs and actual ABI hooks. It adds no GPU consumer.
