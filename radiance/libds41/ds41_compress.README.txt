Experimental projected DS41 compression pool (ratio 1/2, no speculation)

The operator ds41_compress_pool receives projections; it performs no learned projection, norm,
RoPE, index projection, FP4/FP8 cache quantization or cache store. It registers no architecture.
Source equations: official inference/model.py::Compressor at 1bae0e1088993b9b82de08f59de5be5a34e42170
and arch/common/rad_ds41_ref.h::Compressor. Official start_pos=0 prefill / one-token continuation
is generalized to arbitrary sequential chunks using that serial state machine, not new math.

Inputs and exact numerical boundary

Params: M (token capacity), dim (1..1024), ratio (1 or 2), dtype, n_spec (required integer zero).
Operands, in order, with Q packed sequences, T<=M actual original-token rows and S state slots:
  projected_kv  [T,D] dtype, read-only
  gate_scores   [T,D] F32 for ratio 2; absent for ratio 1
  pending_state [S,1,2,D+1] U32, in/out
  state_ids     [Q,1] I32, engine column-0 slots; row pitch may contain other engine columns
  has_init      [Q] I32, ctx_lens: zero cold, nonzero warm (not a Boolean-only input)
  cu            [Q+1] I32, packed original-token boundaries, from 0 to T
  positions     [T] I32, contiguous original-token positions within each nonempty segment
  num_accepted  [Q] I32, optional; every nonempty segment must have value 1
  pooled        [T,D] F32, output indexed by the ORIGINAL input row
  emit          [T] I32, 1 for a completed group, 0 otherwise
  first_position[T] I32, original first token of the completed group, or -1

Ratio 2 requires supplied projected KV and per-column gate scores at F32. With pending values
u,g and current values v,h, each column computes m=max(g,h), a=exp(g-m), b=exp(h-m), then
u*(a/(a+b)) + v*(b/(a+b)), in that scalar FP32 order; no sigmoid shortcut, epsilon or contraction.
Ratio 1 widens the supplied F32/F16/BF16 projection to F32 without pooling or scores. This dtype
flexibility does not authorize changing the trained pipeline: the graph must reproduce the
official upstream projection and cast boundary. Official ratio-2 pooling is F32, followed by
cast to the activation dtype BEFORE RMSNorm. That cast, norm and later pre-RoPE index projection
and cache rotation remain separate graph operations. No normalization or precision change is
hidden here; these are reference numerical baselines, not an FP4/FP8 quality equivalence claim.

An even original position stores the first C2 row and emits nothing; the following odd position
emits a pool whose first_position is position-1. C1 emits every row at that row's position.
Non-emitted pooled rows contain positive zero, not stale memory. Odd chunks and sequences
starting warm at odd positions use the pending pair from the preceding chunk. Active sequences
must own distinct valid slots. Empty segments are ignored, including an inactive state_id=-1,
and their state is untouched. Cold segments require first position 0. Warm segments require the
stored cursor to equal their first position. Last original position must be <= INT32_MAX-1.

Opaque state mapping and unchanged core

Use state_decl(D, requested_state_dtype, max_spec, out): existing LINEAR, RAD_U32, one head,
state_dim={2,D+1}. Nonzero max_spec and forced numeric state-cache dtype are rejected. A future
architecture must not advertise state_f16_ok for this state. Each state's exact word layout is:
  [0, 0..D) pending projected KV as IEEE-F32 bit words
  [1, 0..D) pending gate scores as IEEE-F32 bit words
  [0, D]    next original-token position, exact U32 (bounded to INT32_MAX)
  [1, D]    version/ratio tag 0x44534300 | ratio
For D512 this is 4104 bytes per producer/sequence before pool alignment. It replaces the older
vector-only F32 {2,D} prototype for THIS operator; that helper remains a documented prototype.
Cursor phase determines validity: warm even cursors ignore old pending payload, while odd
cursors require finite pending KV/gates. Cold reset ignores all stale state payload/header.
The two small integer headers avoid float counter precision loss and detect gaps/stale warm
slots; they do not establish model/sequence identity, which remains the architecture's ownership.

Audit: Builder::finish_kv_groups and KVManager::plan_groups size declared U32 bytes; runtime
bind_kv_pools passes the declared dtype and 4D shape unchanged; admission zeroes raw bytes;
KVManager::checkpoint_copy copies raw pitched bytes. --state-cache-dtype is an architecture
preference/opt-in, not an automatic LINEAR numeric conversion. Engine probe treats U32 as
integers. Keeping the entire state opaque makes exact cursor/magic/pending-bit preservation
explicit. No core edit or separate integer slot mapping is required.

Validation and lifecycle restrictions

Whole-batch preflight validates Cu, active slot uniqueness, accepted==1, original positions,
cursor/tag continuity and finite inputs/pending before any output OR state write. Bad IDs/Cu
are checked before indexing state or token rows. Allocation capacities remain the ABI caller's
guarantee. Positive row-major pitches/inner gaps are supported; writable aliases are refused.
GPU compute uses one block/sequence with independent columns and ordered rows, then a barrier
before thread0 publishes emit metadata and the new header. Input arrays are immutable.

The scratch hook reserves four aligned bytes: int32 RAD_OK or a negative validation error at
offset 0. GPU init, preflight and compute run on one stream; any failed preflight leaves every
state/output byte unchanged. Enqueue success is separate from device validation. The experimental
runtime does not yet propagate this flag to request failure; callers/checkers must inspect it.
Never wire a production graph to silently consume stale outputs after a failed flag.

This profile refuses speculation: n_spec must be zero and supplied num_accepted must be 1.
It implements no accepted-prefix replay, pending-state undo, speculative cache publication or
drafter ownership. Adding LINEAR state also retains the already documented WINDOW-prefix
limitation: current core disables WINDOW snapshots when a LINEAR/CONV group exists, so a mixed
topology safely re-prefills rather than claiming fast prefix resume.

tests/ds41_compress_test.cpp checks independent NumPy compressor latents after separate norm,
the pinned serial Compressor across reordered sequences/odd chunks, raw pooling, pending
snapshots, high cursor bit patterns, resets and global failure atomicity. The staged standalone
ds41_compress_selftest.cpp runs exactly 167 tiny synthetic cases only behind --run-gpu, compares
GPU against the independently checked emulator and keeps actual GPU state across chunk calls.
It guards every allocation/read-only input, exact U32 state and scratch flags. Build alone runs
no device work. No production state/cache graph is integrated by these files.
