Isolated DeepSeek-V4.1-1017 Engram gate/residual baseline
========================================================
This is one nonlinear operator, not a serving architecture. Hash history, table
row lookup/SSD cache, upload staging, model/asset identity and the Engram wkv
projection are caller-owned operations. There is NO convolution in the pinned
1017 Engram implementation. No state, allocation, IO or synchronization is hidden
inside either launch path.

Source semantics:
  deepseek-ai/DeepSeek-V4.1-Flash-1017
  1bae0e1088993b9b82de08f59de5be5a34e42170, inference/model.py:328-365.
  Earlier CPU reference: arch/deepseek41/engram_ref.h::gate_residual.
  Independent component fixtures: tests/data/golden/deepseek41-engram.json;
  its provenance records unmodified official forward bodies executed through
  an AST/NumPy CPU facade. This is not a full-model or hardware reduction oracle.

Public entry points
--------------------
  ds41_engram_gate(const RadArgs*,RadStream)             native HIP enqueue
  ds41_ref_engram_gate(const RadArgs*,RadStream) noexcept synchronous host reference
  ds41_engram_gate_scratch(const RadArgs*)                GPU scratch callback

Namespace rad::ds41::engram_gate provides Plan, validate, emulate and shared
scalar equations. The host wrapper substitutes a private four-byte CPU flag;
it never dereferences the generic Ctx device scratch pointer. Register its host
row with no scratch callback and no deferred-device collector. Native GPU uses
scratch status_offset0, with scalar int32 status, for the parent's generic DS41
deferred collector. Registration and core graph integration are separate work.

Fixed seven-operand schema (args.n_t MUST equal7)
------------------------------------------------
  0 x             dtype[T,copies,D]
  1 projected_kv  dtype[T,copies+1,D]
  2 q_weight      F32[copies,D]
  3 k_weight      F32[copies,D]
  4 token_mask    optional I32[T]
  5 residual      dtype[T,copies,D]
  6 gates         optional F32[T,copies]

When optional slot4 or6 is absent, pass data=nullptr,rank=0. Do not remove the
slot or change n_t. Explicit parameters token_mask=0/1 and gates=0/1 must match
presence; active mask values must be exactly0 or1. Other required parameters:
  M       positive token capacity, <=65536; live T is x.shape[0],1..M
  copies 1..8 (released main model4)
  n       D,1..65536 (released main model5120)
  dtype   f32/f16/bf16; x, projected_kv and residual have this same stored dtype
  eps     finite positive FP32-representable epsilon (released norm_eps1e-20)
  clamp   finite positive FP32-representable clamp (official1e-6)

Only positive nonoverlapping pitches are accepted. Output/gate spans must be
disjoint from all inputs and each other, including pitch padding; inplace output
is intentionally refused by this operator. Inputs may share read-only storage.
Every pointer/span/stride/alignment and scratch span is checked before enqueue.

Scalar equation and precision contract
--------------------------------------
For each token/copy, promoted F32 x/key and F32 norm weights:
  hs = sum_d x[d]^2; ks = sum_d key[d]^2
  dot = sum_d ((x[d] * (q_weight[d]*k_weight[d])) * key[d])
  dot = (dot * (rsqrt(hs/D+eps)*rsqrt(ks/D+eps))) / sqrt(D)
  gate = sigmoid(copysign(sqrt(max(abs(dot),clamp)),dot))
  gate = 0 when this token's mask is0
  residual[d] = stored_dtype(x[d] + gate * shared_value[d])

The shared value is projected_kv[token,copies,:], while key for copy c is
projected_kv[token,c,:]. Norms are independent per copy overD, not overcopies*D.
Combined q/k gain is applied to the dot product, never to the RMS sum. copysign
is intentional: +0 yields a gate greater than.5; -0 yields a gate below.5. Using
sign(dot)*sqrt(...) would change the source's zero behavior. Sigmoid is evaluated
with separate positive/negative branches to avoid exp overflow.

Accumulation is an explicit serial scalar F32 baseline; output has ONE storage
cast to the requested dtype. There are no implicit BF16 activation boundaries,
projection quantizers or QDQ stages. It must not be described as an official
whole-model BF16/FP8/FP4 precision profile. Build with -ffp-contract=off and without
fast-math. GPU exp/sqrt and accumulation lowering may differ from the independent
CPU oracle; the native checker allows stated small arithmetic/rounding tolerances.

Transactional payload validation
--------------------------------
GPU launches use the actual supplied stream in order:
  bounded256B-by-value chunks stage Plan into caller scratch+16;
  initialize scratch.status;
  preflight ALL input scalars (even masked tokens) and mask IDs;
  preflight ALL norm/dot/gate/residual computations and requested output casts;
  write residuals and optional gates only if the full batch status remainsOK.

Nonfinite inputs, invalid masks, overflowing intermediate math (including a finite
RMS square sum plus finite epsilon overflowing BEFORE reciprocal-square-root) or nonfinite
output conversions cause a negative status with ALL output bytes unchanged.
This finite-overflow refusal is stronger than the permissive earlier CPU math
reference; it prevents partial outputs and silently emitted infinities. Source
buffers must remain immutable until the ordered operation finishes, as for other
native ops. Aliases/source races are not repaired by preflight.

CPU emulator requires only4B semantic scratch. GPU scratch callback reserves the
status prefix plus rounded staged Plan storage via gpu_scratch_bytes<Plan>(); the
entire reserved span, alignment and operand aliases are checked before ANY
staging. Only status bytes0..3 and actual Plan bytes after16 may change. Metadata
refusals leave scratch and operands unchanged. A successful launch returns only
enqueue success: collect deferred status before sampling/output publication.

Validation files and explicit GPU gate
--------------------------------------
tests/ds41_engram_gate_test.cpp has eight CPU cases covering three dtypes, three
positive pitch patterns, all optional combinations, copies1/4/8, primaryD5120,
independent official-forward goldens, signed-zero/clamp and negative-dot math,
masked tokens, late nonfinites, finite overflow, alias/span/dtype/optional refusals,
staged-Plan scratch overlap and unreadable caller scratch in the host wrapper.

ds41_engram_gate_selftest.cpp is manual native-HIP work, not CTest and not actual
core AQL/Ctx proof. It has136 payload cases plus10 metadata refusals, requires
--run-gpu, exactly one visible gfx1201 and an approved idle window. Each case
caps total tiny device fixture storage (including outer guards/scratch) at1MiB
BEFORE allocation. Inputs, output pitch padding,64B allocation redzones, status
prefix guards and staged-Plan tail are checked. Successful results compare to the
independent earlier CPU reference; FP16/BF16 discrepancies require a rounding
boundary within one stored representable step. Failed payloads preserve both
residual and gates; failed descriptors preserve the entire scratch allocation.

No checker has been run by the authoring child agent. Parent coordinates builds,
registration, GPU execution and any later actual Builder/Ctx lifecycle gate.
