Opt-in Engram HIP staging backend
================================

This source backend implements engram_staging.h's ownership protocol. It is not
registered in any serving graph. Compiling it does not deploy a service or load
model data. Only the separately built, explicitly gated selfcheck runs device
work, against a 217-byte synthetic local IQ4_NL file and sub-KiB device targets.

API and intended order
----------------------
1. HipEngramBackend::create(model_identity, options, &backend) creates one private
   nonblocking stream on options.device and TWO timing-disabled events per fixed
   operation slot. It preallocates bounded host/device ownership slot controls.
   All HIP calls use a device guard that restores the calling thread's device.
2. Pass backend plus ONE shared pinned-host StagingBudget to each generic
   EngramStagingPool. allocate_host uses hipHostMallocPortable; a conservative
   charge includes 4 KiB rounding, HostRowAllocation control allowance and an
   explicit configurable host_driver_allowance (default 64 KiB/allocation).
3. allocate_device(bytes, separate_device_budget, &owner) issues a typed immutable
   device owner, backed by hipMalloc and an explicitly separate charge. Or use
   wrap_device(pointer, extent, shared_lifetime_owner, &owner) for an externally
   budgeted arena. The latter checks hipPointerGetAttributes (device-local,
   unmanaged, correct device) and hipMemGetAddressRange for actual containing
   allocation bounds. The lifetime owner must forbid recycling that suballocation
   until its last reference is gone; pointer attributes cannot prove ownership.
4. pool.submit decodes its requested packed rows into owned pinned staging and
   queues H2D then the upload event on the backend's private compute stream. An
   error can still return an owning non-quiescent ticket. Never infer no work
   from the returned error code.
5. Prefer backend.consume(ticket, callback, user). This establishes the explicit
   promise that all consumers are queued INSIDE that callback on the supplied
   stream and that none will be queued later. It orders the upload before the
   callback, marks consumer ownership before invoking it, catches exceptions and
   ALWAYS attempts to record the final-reader event after callback return/error.
   Cancellation before invocation skips the callback and still seals the scope.
   Partial consumer enqueue followed by an exception is therefore fenced too.
   Callback may not retain the stream or reenter this backend. Other allocations
   referenced by the callback remain the caller's responsibility until quiescent.
6. Advanced callers may use order_upload/wait_upload, enqueue_consumer and then
   finish_readers. finish_no_readers is an explicit no-future-reader proof and
   rejects any prior enqueue_consumer call. These manual callers MUST seal every
   path, including cancellation, exceptions and enqueue failure. There is no
   inference that cancellation means no readers. The private stream is not
   exposed except during the guarded callback.
7. Poll ticket.state()/backend.progress() or drain a sealed ticket. A completion
   requires BOTH the upload and final-reader events. Event flags are reset per
   generation; an unrecorded HIP event's apparent success is never treated as a
   fence. Completion is latched before events become reusable, so old tickets do
   not observe a later operation's events. drain can use successful synchronization
   of this one private stream after an explicit reader seal, including recovery
   from a copy/event-record failure. It never synchronizes/resets other devices.
8. Drop pools, tickets and device owners, then call close(). A false quiescent
   result can also indicate remaining live host/device owners; close does not
   forcibly free them. It stops new work, drains sealed operations, retries failed
   physical frees and destroys the event pool/stream when all ownership is gone.

Failure and quota retention
----------------------------
Event pairs and completion/control resources are reserved BEFORE an H2D operation
is attempted. After any attempted native enqueue, errors retain an owning
completion, even if HIP did not produce a valid event. hipEventQuery/Sync errors
are not quiescence proofs. If no final-reader seal exists, drain remains unsafe
because a future caller could still enqueue a reader. A healthy stream plus the
high-level consume scope avoids that abandoned-scope trap; advanced misuse can
intentionally quarantine indefinitely. Pending records retain backend ownership.

HostRowAllocation's adopt_budget_charge hook is called immediately whenever
allocate_host returns an owner, including an error with a nonnull allocation.
Native allocation wrapper/control creation happens BEFORE hipHostMalloc. Thus
any returned physical pointer has an owner that can adopt the existing charge
before validation/cleanup. After the wrapper's final release, the fixed native
registry calls hipHostFree. Only success (or an allocation that never produced a
pointer) refunds the charge. hipHostFree failure keeps the pointer AND charge in
the registry for retry. hipMalloc owners use the same rule with their separate
device budget and hipFree. No cap is refunded before a successful real free.

The native implementation self-retains its registry while driver resources or
failed frees remain. Keep a backend handle and retry close; dropping the handle
after a persistent driver error intentionally quarantines resources indefinitely.
An externally wrapped arena has a caller-provided deleter/budget: the caller must
apply equally safe free-error accounting there. The backend cannot repair an
opaque deleter that frees/recycles its memory early or loses failed allocations.
External owner destruction occurs outside the registry mutex, including when it
owns another typed buffer from this same backend.

Budgets are distinct: the generic packed-row cache cap, the generic shared pinned
staging cap, device allocations' separate cap, and bounded native metadata/events.
Stats report a conservative native_fixed_allowance; it is an explicit estimate,
not a measured driver-RSS upper bound. Driver/context runtime bookkeeping and
request/completion objects also need the owning engine's bounded resource policy.
max_operations bounds event pairs; max_host_allocations/max_device_allocations
bound registry controls. Defaults are 16/64/64; upper bounds are256 each. The
backend allocates no model table, full cache, arena or weights by itself.

Selfcheck and remaining integration
-----------------------------------
ds41_engram_hip_selftest.cpp requires --run-gpu [device] and gfx1201. It is not a
CTest test and must run only in an approved idle window. It verifies independent
IQ4_NL codebook values, actual pointer/bounds rejection, two layer assets, H2D
completion before reader sealing, an actual D2D consumer, cancellation, callback
exception after a queued reader, event generation reuse, global host/device quota
retention/refund, and device TLS restoration. CPU fake tests separately exercise
partial-submit errors, missing fences and failed-free charge adoption; this tiny
native checker does not deliberately inject real driver faults or reset GPUs.

Production registration, engine request ownership, advanced cancellation cleanup,
real Engram kernel binding, concurrent workload testing and performance tuning
remain separate work. This backend is a conservative correctness baseline. It
holds pinned staging through the last reader, rather than releasing it as soon
as DMA ends; a later split-fence interface could reduce that lifetime.
