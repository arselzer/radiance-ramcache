Experimental local FFN boundaries and existing mHC post

Original scalar GPU/CPU baselines for the exact trained arithmetic boundary in official
inference/model.py::Expert/MoE/Block at 1bae0e1088993b9b82de08f59de5be5a34e42170. No architecture,
expert placement, TP communication or production state lifecycle is registered by these files.
Compile without fast math and with -ffp-contract=off. F32/F16/BF16 activation storage is supported;
numerical dtype flexibility does not imply equivalence to the official FP4/FP8 pipeline.

ds41_expert_act

Params M (route-row capacity), n (intermediate dimension), limit (finite >=0), dtype.
Operands gate[R,n], up[R,n] at activation dtype; route_weight[R] F32; down_input[R,n] at activation
dtype. Inputs are the ALREADY rounded gate/up projection outputs. Widen those values to F32.
If limit>0, clamp gate only above and up on both sides; limit=0 disables clamping. Compute
  activated = (gate * sigmoid(gate)) * up
  down_input = cast_activation(activated * route_weight)
with F32 intermediates and exactly one output cast. Weights must be finite/nonnegative; use ones
for the shared expert. Do not first round SwiGLU to BF16 and multiply afterward. Do not move the
route weight after the down projection. Both changes differ at BF16/F16 and later FP4 boundaries.

ds41_moe_combine

Params M (token capacity), R (route capacity), n, n_expert (1..4096), dtype, tp_world (required 1).
Operands routed[actual_R,n] at activation dtype; expert_ids[actual_R] I32; token_ids[actual_R] I32;
shared[actual_M,n] at activation dtype; out[actual_M,n] at activation dtype. Route IDs/tokens are
bounded and each (token,expert) pair must be unique. A token with no routes receives shared only.
Each routed input must be a COMPLETE, individually rounded expert down-projection output.
For each token, sum those values in ascending expert-ID order using F32, add its completed
shared expert output, then cast once. There is no route weight operand and no second weighting.
Input route order/top-k score order must not alter the ascending-ID reduction.

Existing moe_gather is not the same operation: it weights outputs after down and sums top-k slot
order. Existing swiglu_clamped followed by a BF16 multiply adds an unwanted intermediate cast.
The separate baselines expose these boundaries so a tiny composed graph can test them directly.

TP obligation (not implemented)

tp_world!=1 is explicitly refused. A future tensor-parallel graph needs EACH expert job's down
projection partial output kept at F32, an F32 all-reduce PER EXPERT JOB, and an activation-dtype
cast of that completed expert before ascending-ID combine. The shared down projection requires
the same per-job reduce-then-cast before shared-add. Reducing locally combined expert partials
and casting only their total misses the per-expert rounding boundaries and is not equivalent.
The official MoE's expert-parallel loop sums individually rounded complete expert outputs into
F32; that ownership pattern must not be confused with tensor-parallel partial projections.
No distributed correctness/performance equivalence is claimed by this single-card profile.

mhc_post compatibility

ds41_mhc_post uses the EXISTING mhc_post schema: params M,n,hc,dtype; x[M,n], h[M,hc*n],
post[M,hc] F32, comb[M,hc*hc] F32, out[M,hc*n]. comb is indexed [source,destination]. Sum residual
sources in ascending source order, add post[destination]*x, and cast once. Output is separate;
aliases are refused. Actual libref/ref_mhc.cpp behavior is tested before reuse. libr4d already
implements the matching BF16 operation; the generic experimental launch supplies F32/F16 and
inner-gap verification without changing that schema or replacing an optimized serving kernel.
This is the residual expansion complement of shifted ds41_hc_prepare/ds41_hc_collapse: preparation
emits the NEXT pre-mix, while collapse consumes the previously carried mix.

Validation/checks

The shared metadata validator checks shapes, positive row-major pitches/inner gaps, byte-span
arithmetic, scalar types, writable aliases and four-byte scratch alignment/capacity. Whole-batch
device preflight validates finite inputs/nonnegative weights and all route IDs/duplicates before
any output byte changes. Init, preflight and compute share the caller's stream. Scratch offset 0
contains int32 RAD_OK or a negative error, with only four bytes used. As with existing experimental
math kernels, enqueue success is separate from device validation; runtime status propagation
remains outside this standalone baseline. Inputs must remain immutable for the whole operation.

CPU tests compare independent swiglu/mhc references, actual libref mhc_post, exact expert-order
cancellation and a pre-cast route-weight counterexample. Nine tiny composed tests use synthetic
native IQ2_XS/Q5_K/Q8_0 weights through real packed routed/shared GEMMs, activation, combine and
mhc_post, against real importer/generic-decoded logical-weight oracles. No model payloads are read.
The explicitly gated ds41_ffn_selftest.cpp stages 141 tiny GPU cases with guarded allocations,
read-only checks, output canaries, typed rounding-boundary checks and separately read validation
flags. It is never executed by a build or CTest. Those isolated device checks are not a full
distributed block, production cache lifecycle, model-quality measurement or performance claim.
