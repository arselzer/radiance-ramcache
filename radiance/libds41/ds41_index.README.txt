Experimental floating DS41 indexer
=================================

Three isolated operators implement the serial reference's index equations and
selection rules. They do not register a model architecture or allocate caches.
They use positive pitched row-major views, scratch offset0 int32 validation
status, and init -> whole-batch preflight -> compute on the caller's stream.
Enqueue success is not validation success. The eventual runtime must collect the
flag before scratch reuse and reject a failed step before sampling/publication.

ds41_index_scores
-----------------
Parameters: M(row capacity), key_rows(key capacity), heads(local count),
global_heads, head_dim, sequences(cache sequence capacity), dtype(f32/f16/bf16).
Operands: query[M,H,D], keys[S,K,D], unscaled head_weights[M,H] F32,
sequence_ids[M] I32, visible[M] I32, scores[M,K] F32. Actual M,K,S may be below
their capacities. Each query explicitly names its sequence's key-cache row.

score[row,key] = sum_h relu(dot(query[row,h],keys[sequence_ids[row],key])) *
                       (head_weights[row,h] / sqrt(D) / sqrt(global_heads)).
Dot and head sums follow ascending scalar order in F32. Invisible scores are
-Inf. Only reachable keys require finite values; unallocated/unused cache tails
or other sequences can contain arbitrary bits. Queries and weights must be
finite, including queries with no completed keys. Validation checks IDs and
visibility before accessing selected keys. The graph is responsible for cache
identity/lifetime and for supplying correct per-query visibility:

  visible[row] = floor((original_position[row]+1)/compress_ratio),

capped by completed cache rows for THAT sequence. Broadcasting a chunk-end length
would expose future compressed entries to earlier queries. The CPU composition
test contains future rows in the cache and checks C2 positions independently.

For head TP, sum the local F32 score matrices across all ranks BEFORE candidate
or top-k selection, using global_heads in each rank's scaling. Do not apply the
head scale again outside this op. All ranks must agree on key ordering and
visibility. No collective is hidden inside this operator.

The current key view is a dense semantic layout, not the core's paged K/V tensor.
A direct paged-cache view/gather and its allocation costs remain graph work.

ds41_candidate_blocks
---------------------
Parameters: M,key_rows,block_size,top_blocks. Inputs: scores[M,K] F32 and
visible[M] I32. Output: keep[M,K] U8. Each reachable block is ranked by its
maximum visible score, newest reachable block forced to +Inf, ties by lower
block ID. Selected blocks include their full not-yet-visible tail, as in the
pinned official source. Zero visibility produces all zeros. Invisible input
scores need not be finite; every visible score must be finite.

ds41_index_topk
---------------
Parameters: M,key_rows,topk. Inputs: scores[M,K],visible[M],optional U8 candidate
mask[M,K]. Output: I32 indices[M,min(topk,K)]. Highest eligible scores win, ties
by lower logical compressed position. Selected IDs are then sorted by position,
followed by -1 padding. Any nonzero candidate byte means eligible. Output IDs
are LOGICAL compressed positions: the joint window offset and physical cache
mapping remain caller-owned. Only -1 is padding.

Mask undersupply is explicitly a hard-filter/pad policy. The official Torch
topk can instead fill spare slots with masked-but-visible -Inf entries; its
equal-score tie choice is also not guaranteed to match this deterministic rule.
The pinned1017 configuration uses2048 candidate blocks of8 for index_topk512,
so this undersupply edge is not a full-model capacity claim or an assumed
arbitrary-configuration equivalence. Actual numerical/quality validation remains
necessary before serving.

Implementation and limits
-------------------------
Scoring is parallel over query/key pairs. Selection uses a bounded worst-first
heap, then sorts selected IDs into position order. One thread per query is a
correctness baseline, not an optimized large-context indexer. Max selections4096
use32KiB dynamic LDS. Bounds: M<=65536, K<=1048576, local heads/head dimension
<=1024, cache sequences/global heads<=65536. Descriptor byte arithmetic, writable
aliases and scratch wrapping are checked before dispatch. All outputs remain
untouched after any device payload validation failure.

Independent CPU tests compare heap results with the serial oracle's partial_sort
across random sizes/ties, max capacity, pitches, masks, zero visibility and
per-original-position C2 composition. The explicitly gated GPU checker passed169
tiny cases on onegfx1201, including D128/local heads8/global heads32, max heap
allocation, selected/unselected invalid payloads and guards. These are native
HIP-stream checks; actual core AQL/Ctx launch validation is a separate gate.

Numerical boundary
-------------------
These are FLOATING semantic operators using supplied unscaled F32 head weights.
The official path has BF16 weights_proj/scaling and FP4 q/key quantization, with
different reduction/rounding boundaries. Those are not emulated. Passing a
previously scaled BF16 weight would both alter the contract and double-apply the
scale. Packed checkpoint preservation does not establish official arithmetic,
model accuracy, memory fit, TP4 execution or throughput.
