Experimental GPU baselines for existing DS41 mathematical schemas

The four exported launch names are ds41_hc_prepare, ds41_hc_collapse, ds41_router_topk and
ds41_sparse_attn. They use exactly the existing libref ds41_* operand/parameter schemas.
No production architecture, state lifecycle, routing dispatch or model activation is registered.
This implementation computes scalar FP32 equations on GPU, with F32/F16/BF16 activation storage.
Prepare always returns F32 pre/post/comb; router always uses F32 logits/weights and I32 ids.
Compile without fast math and with -ffp-contract=off. These are correctness baselines, not
optimized or measured kernels. Current limits: hc=2..8, Sinkhorn iterations=1..256,
router experts<=4096, sparse topk<=4096 and head_dim<=1024. Actual rows may be below M capacity.
Dimensions used for launch counts fit signed 32-bit geometry. Input/output tensor views may have
positive inner gaps and padded rows/heads; transposes, overlapping views and output aliases are
refused. The ABI provides geometry rather than allocation capacity, so callers still guarantee
that every advertised source/destination span is allocated and remains immutable during use.

Scratch and asynchronous error contract

Wire ds41_math_scratch as the RadScratchFn for all four GPU rows. Semantic CPU
emulation needs a four-byte aligned status flag. Native scratch includes a
16-byte status prefix and the common rounded, chunk-staged Plan reserve; the
entire reserve is checked against operand spans before any enqueue. A successful
launch return establishes enqueue only. Scratch flag0 means completed validation
passed; negative RAD_E_* means failure. Null/undersized/misaligned or overlapping
scratch is refused synchronously, preserving flag/output bytes.

Each launch enqueues Plan staging, flag initialization, whole-batch input
preflight, a SEPARATE whole-batch derived-arithmetic preflight, then publication
on the same caller stream. Both preflights finish before any output writes.
The output-free dry run checks FP32 intermediate arithmetic and final storage
conversion, including finite inputs whose products/sums overflow or whose F16 /
BF16 output cast would become infinity. Such faults return/latch RAD_E_INVAL and
leave every output byte unchanged, including earlier rows/heads. Publication
repeats identical equations with immutable inputs. Arbitrary device faults or
concurrent caller mutation do not gain rollback. Sparse IDs are checked before KV indexing; -1 is
the only padding value. Only selected KV rows require finite values. Sinks may be finite or -Inf.
The first error stored by concurrent validators is unspecified if several inputs are invalid.

Launches never allocate or synchronize, and never inspect device payloads from the host.
Therefore RAD_OK returned by launch means successful enqueue, not successful device validation.
A standalone checker must synchronize and read the scratch flag. The registered
experimental GPU module supplies the optional scalar deferred-status collector;
Core awaits it before sampling/state publication. The current opted-in Engine
profile remains TP1/eager with fatal semantic failures; see
../core/runtime/deferred_status.README.txt. No public status operand/schema change.
HOST rows use private CPU flags and synchronous errors. No production architecture
or full-model support is implied by these experimental row registrations.

Equations and checks

ds41_math_impl.h is the same scalar row implementation compiled for CPU emulation and GPU.
Expected results in tests/ds41_math_test.cpp use the independently written pinned semantic
reference in arch/common/rad_ds41_ref.h. Prepare emits NEXT shifted gates; collapse consumes
the supplied previous_pre. Sinkhorn adds hc_eps after the initial row softmax, always performs
column normalization, and performs a fresh row normalization only after iteration zero.
Router uses sqrt(softplus(logit/temperature)); correction changes selection IDs only, ties sort
by increasing expert ID, and topk=1 bypasses normalization. Sparse attention uses a shared K=V
latent; the sink contributes a logit and denominator, with zero value. No selected keys plus a
disabled sink gives positive zero. Float products/sums follow ascending reference loop order.
GPU exp/log/sqrt can differ slightly from the CPU math library; the device comparison needs
small FP32 tolerances and explicit final F16/BF16 rounding checks.

The router dry run never reads output weights: selected raw weights use a bounded
2*experts+topk float workspace (at most48KiB), then normalization/scaling is
validated before publication. Prepare uses144floats; sparse uses topk+head_dim;
collapse needs no workspace. Scalar loop/reduction order, topk1 normalization
bypass, ordinary underflow-to-zero, and existing all-padding behavior remain.
Representable signed zero remains valid; overflow is refused, not saturated.
Tests/ds41_math_derived_test.cpp covers finite-source and storage-cast witnesses,
late-row/head atomicity, previous-output/NaN poison, and good-bad-good reuse.

These files are original baseline implementations of equations documented by the existing
reference. No third-party GPU kernel source is copied. CPU emulator tests do not establish
device correctness; a separate staged GPU checker must compare actual launch results/flags.
