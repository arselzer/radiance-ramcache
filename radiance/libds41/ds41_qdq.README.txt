Experimental BF16 quantize/dequantize candidate: ds41_qdq_candidate
================================================================

This explicitly named candidate isolates the pinned 1017 activation-precision
equations from physical cache compression. It emits BF16 values, not packed FP4
or FP8 bytes, saves no cache memory, and changes no default model profile. The
ordinary official TileLang kernels have not been executed in this environment.
Matching this mathematical reference is not full-model accuracy or logit parity.

Profiles, operand ABI and rounding
---------------------------------
Required parameters: M (row capacity), n (vector width), profile, masked (0/1).
Fixed operands: input [actual_rows,n] BF16; optional emit [actual_rows] I32;
output [actual_rows,n] BF16. Unmasked emit must be absent (null, rank0).
Positive nonoverlapping element pitches are accepted. Actual rows are 1..M,
M<=65536; n<=1024 and divisible by the selected group size. This is an
out-of-place operator. Output is disjoint from input, mask and all scratch.

  profile          group   value code       scale
  window_fp8       32      E4M3             E8M0 power of two
  compressed_fp4   16      E2M1             E4M3
  index_fp4        32      E2M1             E8M0 power of two

The reference equations and explicit stronger refusal policy are documented in
arch/deepseek41/qdq_ref.README.txt. Every active group reduces a finite absmax,
applies its profile's scale floor, rounds the scale, clamps and rounds normalized
values, dequantizes in F32 and rounds to BF16. Signed zero is retained. Index
scale floor 2^-126 can produce BF16 +/-2^-127; those words must not flush to zero.

This candidate refuses nonfinite active inputs, scale/quotient/dequantization
overflow and nonfinite BF16 casts. In particular E4M3 scale magnitudes above464
refuse rather than adopting an unspecified saturation policy. Observed Torch
CPU saturation behavior does not establish official TileLang overflow behavior.

Whole-batch payload refusal and lifetime
---------------------------------------
All masks are checked before any input payload. Mask0 skips that input row and
writes positive-zero BF16 only on a successful whole-batch call. Bad masks,
nonfinite active payloads or derived arithmetic refusal leave the entire output
unchanged, including inactive rows. Inputs must remain immutable until completion.
This is payload refusal atomicity, not rollback after arbitrary device faults.

HOST launch uses a private four-byte CPU status and never dereferences caller
DEVICE/NULL/PROT_NONE scratch. It rejects unsupported host rounding/FTZ/DAZ state.
GPU launch stages a checked Plan through the common 256-byte transport; the
entire native scratch reserve is alias-checked before any enqueue. Ordered GPU
phases reset status, validate masks, preflight every group, then write. Four
logical wave32 groups share each 128-thread block; 16-wide groups still execute
all32 shuffle lanes. A uniform lane0 status broadcast precedes any early exit.

The GPU row opts into the scalar deferred-status collector. Core must complete
that check before publishing dependent state or sampling. Scratch/status storage
must remain alive until ordered collection. Current opted-in Engine policy is
TP1, eager, without speculation/ahead replay; this operator does not remove that
restriction or supply distributed failure cancellation.

Compiler and independent evidence
---------------------------------
CPU and GPU targets explicitly compile with -fno-fast-math -ffp-contract=off.
The local HIP7.1 / LLVM21 gfx1201 toolchain exposes neither CUDA __fdiv_rn nor a
linkable OCML RTE division helper. The candidate therefore uses ordinary F32
division under those flags. Actual device quotient-tie tests are mandatory;
source intent or CPU agreement cannot establish a different compiler's lowering.

The scalar GPU encoder uses bit rounding / explicit midpoint parity; the CPU
reference uses independently ordered codebook search. Tests also consume saved
actual Torch2.14.1+cpu BF16/E4M3 casts and E8M0 decoding, plus exact Fraction FP4
codebook fixtures. A separate CPU-only helper executes the unchanged installed
AMD host FP4 conversion on64 boundary inputs. None is relabelled TileLang/GPU
execution. Source and fixture hashes are recorded alongside the research reports.

These establish this local compiled candidate on one9070XT under tiny fixtures.
They do not establish all inputs/toolchains, official lowering, packed cache ABI,
full architecture wiring, TP4 communication, model fit, quality or performance.

Standalone checker: ds41-qdq-selftest --run-gpu [device]. It is never automatic
CTest. Run only within the approved idle window after checking service health.
