Experimental DS41 projection/norm/rotary bridge (source only)
===========================================================

These two standalone operators follow the floating scalar equations of pinned official
inference/model.py commit 1bae0e1088993b9b82de08f59de5be5a34e42170: RMSNorm (281),
precompute_freqs_cis/apply_rotary_emb (369/392), Compressor (437), Indexer (527),
and Attention (676-784). They do not register a serving architecture or allocate model state.
They reproduce the serial independent DS41 oracle, not every Torch reduction/backend bit.

Storage boundaries are explicit
-------------------------------
ds41_rmsnorm params: M,n,eps,a_dtype,y_dtype. Tensors are x(rows,n), gain(n) F32,
and y(rows,n). Inputs/output may be F32/F16/BF16 independently; the input tensor is already
at its intended storage precision. Each row accumulates ascending F32 squares, computes
rsqrt(mean+eps), multiplies x*inverse*gain in F32 and stores once in y's declared dtype.
Gain is used directly, without a Gemma-style +1. Positive inner/outer pitches are supported.

For a ratio-2 compressor, the supplied projected KV and score values are F32. The pooling
operator leaves the result F32; the graph MUST cast that pooled result to the activation
dtype before passing it to norm, then retain norm's activation-dtype output. Running norm
directly on the unrounded F32 pool changes the trained path. Ratio-1's projected input also
needs its official BF16 projection boundary; dtype flexibility does not authorize removing it.
Projection quantization/casts are graph responsibilities, rather than hidden transform work.

ds41_rope_tail params: M,heads,head_dim,rotary_dim,dtype,inverse (0 or 1). Tensors are
x(rows,heads,head_dim), positions(rows) I32, pairs(P,rotary_dim/2,2) F32, and out shaped
like x, with the same dtype. Positive pitches, including gapped inner elements, are supported.
The final rotary_dim elements are adjacent real/imaginary pairs. Prefix bytes are copied
unchanged. Pair multiply/add runs in F32, then stores once at the activation boundary.
inverse conjugates the supplied pair by negating its sine. Output is separate; no aliasing
of output and any input is accepted. Selected table pairs must be finite and unit magnitude
within F32 tolerance. Unselected table rows are not inspected or consumed.

The existing generic RMSNorm equation is compatible with gain, wadd=0 and mult=1 when the
input/output storage boundary is correct. The existing generic partial rope operates on the
leading region and does not expose this explicit inverse; passing DS41's full latent through
that API would rotate the wrong columns. This bridge states the tail and inverse directly.

Positions and operation ordering
--------------------------------
Queries and sliding-window KV use each original query/token position. A completed compressed
latent and its derived index key use the FIRST original position of their group, e.g. C2
emits groups at positions 0,2,4, not completion positions 1,3,5 or compressed indices 0,1,2.
Inverse output RoPE uses the corresponding query position. positions must lie in [0,P).
There is no -1 padding interpretation: compact completed compressor rows before the call.

Preserve the unrotated normalized compressor latent for wk -> index k_norm -> index-key RoPE
before rotating/quantizing the latent for compressed KV. The index path and the latent cache
need distinct outputs or a proven lifetime; this operator never silently overwrites a source.
At compressed attention layers, the official layer frequency table uses compress_rope_theta
and YaRN for ALL of its query, window-KV, compressed-latent and index branches. Window-only
layers use rope_theta with original_context=0 (no YaRN). The checked host select_spec helper
selects these per-layer settings from already-validated DS41 metadata, without source weights.

Explicitly bounded host table construction
------------------------------------------
build_pairs requires both an explicit position count and a caller-provided maximum byte
budget. It checks spec/derived frequencies, overflow and the budget before allocation, and
stages the result so a failure leaves caller output/receipt unchanged. No training context
length is inferred for allocation. The receipt reports positions, rotary dimension and native
F32 pair-table bytes; deployment would need to account for host/device copies in its memory
receipt and cache/reuse the table. The hard synthetic profile cap is 1,048,576 positions and
1024 rotary dimensions; a caller's smaller memory budget remains authoritative.
The F32 angle, inverse-frequency interpolation and adjacent pair order follow the pinned
equations. CPU tests independently check positions up to 262143 against precomputed NumPy
goldens as well as the serial reference. No frequency table is a model weight.

Safety/status and scope
----------------------
The caller supplies aligned scratch >=4 bytes; status is the I32 at offset 0. Host metadata
validation checks shapes, pitches, overflow, types and writable aliases before enqueuing.
Same-stream initialization and complete-batch payload preflight precede compute. Invalid
positions/nonfinite consumed values/malformed selected pairs set a negative device status
and leave ALL output bytes unchanged. Only four scratch bytes are written; extra capacity is
untouched. A launch return RAD_OK means ENQUEUE success. The graph must read/propagate the
device flag before treating output as valid; that production lifecycle is not integrated here.
All inputs and selected table rows must have actual storage matching their declared RadTensor
geometry; this ABI does not provide independent allocation byte capacities.

F32 equations and explicit F16/BF16 boundaries are a correctness baseline. Official FP4/FP8
activation/cache quantizers, BF16 projection accumulation, distributed reductions and backend
reduction trees are not modeled or claimed equivalent. In particular TP projections must
reduce the complete F32 projection before its required activation cast and subsequent norm.

tests/ds41_transform_test.cpp has seven CPU cases, including comparison with actual generic
libref RMSNorm, independent rotary goldens and compressor -> BF16 -> norm -> first-position
RoPE composition. ds41_transform_selftest.cpp is a standalone checker gated by --run-gpu;
it checks 261 tiny device cases and 14 descriptor failures, with guarded allocations, readonly
inputs, padding, explicit status and storage-boundary comparisons. Neither is a serving path.
