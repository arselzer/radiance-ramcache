Tiny serial DeepSeek V4.1-Flash-1017 block/head fixtures

Reference: deepseek-ai/DeepSeek-V4.1-Flash-1017
commit 1bae0e1088993b9b82de08f59de5be5a34e42170 (MIT).
The generator pins exact SHA256s for inference/model.py and inference/kernel.py.
It extracts the original Block, RMSNorm, Gate, Expert, MoE and Engram forward
bodies using the AST, omitting only decorators/annotations, and executes them
with the sibling Engram NumPy CPU facade. Sinkhorn follows the explicit math in
hc_split_sinkhorn_kernel; no TileLang kernel is executed.

Reproduce from the Radiance source root:
  OPENBLAS_NUM_THREADS=1 python3 tests/data/golden/deepseek41-block-generate.py \
    /path/to/pinned/official/reference tests/data/golden/deepseek41-block.json

The source path contains inference/{model,kernel}.py. NumPy and the sibling
checked-in deepseek41-engram-generate.py are the only generator dependencies.
Ordinary C++ tests read only the checked-in JSON. No model weights, PyTorch,
GPU, online dependency or external absolute path is needed by ordinary tests.

Both f32 and explicit BF16-boundary cases are provided. These are tiny synthetic
weights: four streams, dim4, two layers, three routed experts at top2 plus one
shared expert, and an Engram contribution before layer1 attention. The isolated
block starts from asymmetric residual copies and a nonuniform previous pre mix.
Full-token fixtures start from replicated embeddings and one-hot pre, run two
blocks and collapse using the LAST FFN pre before final norm/FP32 logits.

The attention sublayer is a supplied synthetic linear callback in these fixtures.
They validate block/callback integration, not the full attention algorithm or its
source caches. The separate attention reference has its own state/math tests.

Expert activations are clamped (gate upper-only, up both sides); routing bias
selects IDs but mixture coefficients derive from unbiased sqrt-softplus scores.
Routing weights multiply the intermediate activation before down-input rounding.
FP32 accumulation follows ascending expert IDs before the shared expert is added.

Comparisons use absolute 8e-6 plus relative 2e-5 for floating reduction differences;
selected routing IDs match exactly. BF16 activation boundaries are explicit, but
these fixtures do not simulate actual MXFP4/FP8 activation/cache quantization or
establish packed-kernel numerical quality or model-scale serving readiness.
