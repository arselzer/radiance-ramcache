Actual Core/AQL compressor pipeline checker, explicit manual execution only

New source ds41_aql_compressor_pipeline_check.cpp. No *_test.cpp name, automatic
CTest, model weights, QDQ registration, full architecture, TP collective or
serving configuration changes. Parent owns CMake/build and separately authorized
idle-device execution. Child wrote/reviewed source only; no compilation/GPU run.

Suggested isolated build target name ds41-aql-compressor-pipeline-check, following
the existing manual AQL targets: HIP-enabled rad_core, existing WHOLE_ARCHIVE
link/export arrangement so actual libds41 HIP launches interpose through Core
AQL, ENABLE_EXPORTS, and dependency on the isolated26-row libds41 module. Include
core/abi/tests paths and compile -ffp-contract=off. No libquant/model/golden file
dependency. This checker uses direct real sched/batch.h, mem/kv.h and Pools;
no scheduler fake implementation or malloc-backed substitute is included.
The QDQ candidate/27th-row work is separate and unnecessary for this target.

Only run during the parent's user-approved idle window:
  env -u HIP_VISIBLE_DEVICES ROCR_VISIBLE_DEVICES=0 \
    <isolated>/tests/ds41-aql-compressor-pipeline-check --run-gpu \
      --home <isolated>/radiance_home
Repeat as a NEW PROCESS with --host-kargs. The ordinary main gate requires both
--run-gpu and --home before explicit device/plugin queries or allocations.
Linked HIP registration constructors can run before main; that limit is explicit.
The checker requires actual AQL, exactly one visible gfx1201 and no HOST fallback.

What executes
-------------
Real registered compressor -> completion -> emitted store, unmodified launches:
  ds41_compress_pool
  ds41_compress_finish
  ds41_latent_store_emitted
Builder declares ordinary guarded DEVICE tensors, FULL paged latent storage and
opaque U32 LINEAR compressor state; binds both groups to the actual layer; sets
real buffer read/write lifetimes; and finishes/resolves the actual GPU rows.
Ctx binds real KVManager pool regions. All three rows must have actual deferred
status collectors. There are no capture/replacement launchers or fabricated
runtime RadTensors. Issue uses public RAD_B_N and RAD_KV operands plus actual
BatchBuilder device I32 coordinates. Deferred status means eager passes; tapes
are explicitly disabled and pass_counts().played must remain0.

Each profile runs two successful odd chunks over two sequence identities:
  A3+B3, starting at original positions0/0
  B4+A4, resuming at original positions3/3
The second pass changes packing order while retaining each sequence's original
U32 state slot. Both finish at cursor7 with original projected row6 pending.
A third admitted sequence has a literal0xDEAD0000+i raw-word state guard and is
never used. Profiles are F32 and BF16 activation; projection/pooled values and
pending opaque state remain F32/raw U32 as specified by the compressor.
Constants are hidden/latent D8, compression ratio2, original-token block4,
rotary tail4, maxT8/maxSequences3/maxContext16, one actual device.

Real BatchBuilder supplies DEVICE I32 positions, ctx_lens, cu_seqlens, LINEAR
state_index and FULL slot_mapping. No caller-side HOST payload dereference of
these device arrays occurs before/during the operator chain. Metadata upload,
guarded input uploads, the three actual launches/collectors and status capture
share the same real Core stream. There is no payload readback, HOST compaction,
CPU bridge or synchronization inserted between operators. await_device_status
and a successful stream drain precede all validation/readback and publication.
The HOST reads of BatchBuilder coordinates happen only after that complete pass.

Independent expected results and ownership checks
-----------------------------------------------
CPU expectations use existing independent ref::Compressor with explicit F32 or
BF16 cast/RMS boundaries and ref::rotary at the completed row's FIRST ORIGINAL
position. Pooled values separately use the literal two-row softmax-pooling
formula. Expected pending state words are literal bit_cast<F32> projection/score
values, original cursor and0x44534302 magic, not generated by a native emulator.
Physical cache addresses are independently derived from real KVManager block
tables plus state::physical_byte; actual device slot arrays must agree afterward.

Every guarded public buffer is read/checked in full, including prefix/suffix
rows, unused capacity and immutable inputs. I32 masks/first positions/statuses,
inactive positive-zero outputs and guard bytes compare exactly. Active F32
numeric cells use5e-6+5e-5*abs(expected); active BF16 cells allow one finite
stored ULP for device exp/sqrt arithmetic. Actual emitted cache cells must ALSO
match the actual rotated DEVICE tensor bits EXACTLY at each independently
computed physical address. Only current emitted cells allow numeric comparison;
all other pool bytes, literal U32 state/header words, prior cached GPU bytes,
third-sequence state/cache and the tail guard must compare bit-for-bit. Verified
prior GPU cache bytes become the exact preservation baseline for the next pass.
Registered launch pointer identities are checked unchanged for every band.

Bounded allocation receipt
-------------------------
Pools receives explicit1MiB weights and1MiB KV budgets, host_pool0. The unused
weights pool remains a real minimum allocation; it is not hidden/faked/borrowed.
KVManager caps paged tokens64 before carve. Logical KV/state plus a256-byte
tail guard must be<64KiB; each guarded tensor is<16KiB; actual Program arena
is<=128KiB. No large model payload or full-VRAM auto budget is requested.

Parent-approved total cap is8MiB requested/committed data, allowing both minimum
pools to round to2MiB. BEFORE Pool allocation the checker reads supported VMem
granularity and bills BOTH1MiB budgets rounded to
max(RAD_ALIGN_POOL,VMem granularity). It rejects a larger rounded requirement
when this bound plus planned arena, BatchBuilder device slab/pinned ring and
512KiB bounded checker-HOST-staging allowance would exceed8MiB. After carve,
reported actual pool commitment must fit that conservative pool bound.
Virtual KV reservation requested/bounded size is printed separately from actual
commitment; reserving an address range is not a claim about backed VRAM bytes.

The BatchBuilder device slab comes from its actual public device_bytes helper.
The pinned ring bound follows batch.cpp's three mirrored host/device carves plus
worst table ranges and256-byte alignment, for this no-media/no-adapter fixture.
Guarded public tensors are a SUBSET of the Ctx arena and are not double-charged
in the total backing receipt. Used logical tensors/cache/state plus conservative
staging checks remain<1MiB. Peak one-profile receipt prints requests, commitment,
rounding bound, actual arena/tensor subset, device batch slab, pinned ring bound,
HOST staging allowance and logical KV/state guard span. Profiles run serially.
Driver/module metadata, allocator/page overhead beyond that stated conservative
pool bound, Core stream/queue/kernel-argument/bounce rings and device-status
runtime metadata are additional and explicitly excluded from the data receipt.

Teardown and scope
------------------
The whole Pipeline owner is allocated BEFORE init so partial initialization
still has an explicit cleanup owner. Successful drain precedes Ctx shutdown,
BatchBuilder fini, stream destruction and eventual real Pool destruction. An
unproven drain retains the WHOLE owner/plugin/Pools/Batch/Ctx until process exit;
it does not free buffers behind queued readers or claim queue cancellation.
No arbitrary fault recovery is established by this gate.

Exactly FOUR successful passes and TWELVE actual operator issues are required.
There is intentionally no bad-payload path in this checker. Separate component
tests cover deferred errors, but this multi-op chain does NOT claim global
state/cache rollback: later GPU operators may already be enqueued after an
asynchronous earlier refusal, and a valid earlier compressor may have mutated
LINEAR state before a later op fails. Such a profile is fatal/fresh-fixture only.
This gate proves successful odd-chunk persistence and ownership only if its
parent-owned native AQL runs pass. It is not GLM/DS41 full inference, official
QDQ/TileLang parity, a262K-context fit, multi-rank safety or performance evidence.
