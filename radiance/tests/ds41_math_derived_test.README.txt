Derived arithmetic refusal for the four existing DS41 scalar baselines

The original source validated finite inputs and selected IDs but never checked
FP32 arithmetic or final F16/BF16 conversion before output writes. Finite inputs
can overflow normalization/dot products, routed scaling or sparse numerators;
a finite collapse result can overflow its actual output dtype. Existing scalar
reference equations share this numerical limitation, so ordinary oracle agreement
alone did not establish refusal of these inputs.

This change preserves the original equations, ascending reduction order, router
ID tie order, correction-only selection, topk1 normalization bypass, shifted-mHC
gates, Sinkhorn epsilon placement and all-padding/-Inf-sink positive-zero policy.
It adds a conservative checked domain: each derived FP32 arithmetic value and
actual output conversion must remain finite, with positive required divisors.
Intentional -Inf sparse padding/disabled sink and exp/sigmoid underflow to zero
remain permitted. Overflow of a finite score difference is refused rather than
silently treated as a legitimate -Inf mask. No rescaling, saturation, alternative
stable algorithm or model defaults are introduced.

Shared checked_job<Write> helpers execute identical expressions for validation
and publication. CPU emulation validates all source payloads, then dry-runs ALL
jobs, then publishes. GPU enqueues source preflight, a separate derived-preflight
kernel, then publication on the same stream. All derived errors latch RAD_E_INVAL
at the existing scalar flag before any public output writes. No host readback,
allocation, synchronization, ABI/status-schema or core change is added. Inputs
must remain immutable through both phases, as the existing operand lifetime
contract already requires. The public launch return still means enqueue success;
read the existing deferred validation status before accepting outputs.

Router dry-run never reads output weights. Selected raw weights use an additional
K floats, so workspace is 2*experts+topk <=12288 F32 values (48KiB), independent of
batch size. Its other existing workspaces retain their bounds. GPU descriptors
continue through the existing common staged Plan; no larger by-value kernarg.

Seven CPU TEST cases exercise normal independent-reference results across three
activation dtypes and both packed/pitched views, and accepted-finite failures:
late prepare square/dot overflow (all three activation types), Sinkhorn zero
column divisor, collapse FP32 overflow, finite FP32 -> F16/BF16 overflow, router
normal-temperature quotient and topk1 scaling overflow, sparse numerator overflow
with finite scores/probabilities, and final-head F16 score overflow. Earlier safe
jobs' output, all inputs, padding and guards must remain unchanged on refusal.
Good -> bad -> good resets use the same Case storage. Existing tie/zero/padding
policies are checked; an explicit NaN-filled router output dry-run proves that
output weights are not used as hidden intermediate storage.

These are bounded CPU/emulator tests, not native execution or model-quality
proof. Parent owns builds/native checker integration and execution. Compile with
no fast-math and -ffp-contract=off as for the unchanged independent reference.
