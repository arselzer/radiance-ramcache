What it actually tests
The actual converter creates a six-entry old synthetic container from BF16
expert/trunk source, and a candidate from different supplied FP8 experts and
BF16 trunk. Each has the same three uneven PLE source pieces and authenticated
BF16 global/alias scalars0x3951, but their PLE code streams deliberately differ.
The source configuration includes quant_method=fp8 and block128x128. All positive
calls explicitly --set quantization_config.quant_method=, as converter-v2.

Four RETAIN entries are PLE, the BF16 trunk, protected GU, and protected DN.
Two NEW entries are normal native FP8 GU/DN. Old/protected BF16 values are
nonzero positive dyadics; new retained trunk values are negative; new protected
source is mixed finite FP8 with supplied block scales. Actual candidate outputs
must demonstrably differ from old protected/trunk. Therefore a silent numerical
fallback cannot satisfy the final retained-byte checks accidentally. Original
vs new PLE codes also differ; its one immutable global scale is intentionally
identical. This is not a learned model/checkpoint or precision-recovery test.

The old recipe gives normal/protected/trunk a BF16 cast. The hybrid recipe
REMOVES the normal-expert rule entirely, retains the old protected/trunk casts
and EXACT old PLE option spelling. The actual new expert path must be unquantized
raw FP8 code/BF16 scale copy. Normal class0 and protected class1 each have one
expert and slots0(GU)/1(DN); separate synthetic movement classes keep each file
stride homogeneous. This is not the production class/TP assignment or serving.
The converter-only test_import_read row only describes planes and refuses launch.

Complete retained-set preflight
A candidate container is generated by the real converter WITHOUT reuse. Its
metadata is thus the real converter's planned encoding/recipe result, rather
than a second hand-written planner. On tiny fixtures only, this includes a
numerical candidate conversion, not just a metadata query. No full-model workflow
should duplicate a whole candidate artifact merely to obtain metadata: a narrow
metadata-only preflight remains a future full-conversion gate.

Before the only --reuse call, guarded_hybrid_convert requires exact six-name
coverage and disjoint4-retained/2-new sets. It checks the exact current converter
predicate for every retained entry: encoding, quantizer string, options_text,
rank, ALL shape slots, and expert layer/ID/slot. It also compares candidate recipe
metadata against actual Recipe::match/options_text, and verifies native block128
FP8/BF16 normal output with unchanged logical shapes and expert identity. This
is OUR wrapper refusal, not a new strict mode in stock rad-convert.

An actual options-drift probe uses equivalent scalar spellings (truncated old
legacy decimal vs exact dyadic decimal). Encoding and BF16 scale remain equal,
but recorded option text differs, so the wrapper must refuse before invoking
--reuse or creating any hybrid output. Incomplete/overlapping retained sets also
refuse. Nine read-only copies of actual entry metadata exercise rank, leading
shape, unused shape tail, quantizer, options, encoding, layer, expert and slot
predicates. They never change mapped files or Core state.

After actual --reuse, every retained plane is compared byte-for-byte with the
old artifact, and all new normal expert code/scales are compared against the
independent physical byte generator (GU gate then up, then their scale rows;
DN exact code/scales). Every old artifact plane is itself checked against its
independent BF16/FP8 byte source. Final metadata/coverage is rechecked. The
verbose actual converter log must contain EXACT four known per-weight 'reused'
entries and EXACT two normal 'as is' entries, with no unknown/duplicate evidence.
Full source fingerprints before/after are a noncryptographic mutation regression
witness, not hostile-writer security. No expected bytes come from observed
hybrid output or a round-trip decoder. No comparison tolerance is used.

The linked real converter/Core/module allocator footprint is not claimed to fit
these logical fixture byte caps or to be a process RSS quota.

Scope limits
This can prove a deliberate synthetic hybrid route using current --reuse; it
does not authenticate complete real-model payload hashes, tokenizer identity,
all retained source encodings, full-model scale alias/preflight, full-model
conversion/storage budget, or actual inference accuracy. Before a real artifact,
require exact retained/new name closure, complete source/old generations and
headers, strict reuse admission, independent streaming equality of EVERY plane,
full output checksums, reviewed tokenizer/config provenance, and owned atomic
publication. It is explicitly different provenance, not the CLI's default
same-checkpoint reuse assumption. No full conversion is authorized by this test.
